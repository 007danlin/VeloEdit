# Локальные киноприёмы VeloEdit

Редакция: 9 октября 2026. Источник подготовки: [Melies Cinematic Techniques](https://melies.co/cinematic-techniques). База включена в приложение; при чтении карточек и выполнении планов сеть и переобучение модели не используются.

## Что подготовлено

- [Реестр всех 424 карточек](registry.md): 13 разделов, ссылка, дата извлечения, SHA-256 страницы, решение и причина для каждого приёма.
- [Локальная база](../../Resources/CinematicKnowledge/cards.json): 100 переработанных карточек с русскими формулировками, английскими названиями и поисковыми вариантами. Все 80 карточек приоритетных разделов подготовлены подробно: Editing — 23, Framing — 25, Composition — 32. Ещё 20 выбраны из остальных разделов.
- [Карта инструментов](tool-map.md): разрешённые команды отделены от возможного будущего способа реализации. Например, `trim + cut` у match cut — описание монтажного механизма, разрешение на автоматическую склейку отсутствует.
- [Типизированные операции приложения](application-operations.json): 40 настоящих конструкторов `DirectorToolCall`, их параметры, места определения и условия исполнителя. Словарь `DirectorEditingTool` содержит 61 название инструментов; названия словаря не следует считать 61 независимым исполнительным контрактом.
- [Пробелы зрительного анализа](analysis-gaps.md): что знания уже объясняют и чего текущие наблюдения ещё не доказывают.
- [Результаты испытаний](test-report.md), [MP4-примеры](examples.md), машиночитаемые результаты и разметка исходников находятся локально рядом с отчётом; личные материалы и сырые результаты проверки исключены из Git.

Полный аудит: 8 «Применим», 85 «Полезен для анализа», 317 «Отложен», 14 «Исключён». В подробной базе: 8 применимых, 85 аналитических и 7 отложенных. Отложенные карточки вне подробной базы остаются в реестре: их английское название можно распознать и объяснить отказ, но подробного руководства или автоматического исполнения для них пока нет.

Каждая подробная карточка содержит источник/дату, статус и обоснование, цель, признаки, нужные данные и ограничения уверенности, перечень команд/эффектов/переходов, порядок работы, условия отказа, положительный и неподходящий примеры, проверку результата. Иллюстрации, целые веб-страницы, рекламные блоки и генеративные промпты не поставляются. Формулировки источника переработаны; его художественные рекомендации не объявлены универсальными правилами.

## Исполняемая часть

| Приём | Команда | Реальный ID / параметры |
| --- | --- | --- |
| Наплыв | `addTransition` | `cross-dissolve`, соседняя пара, duration по реестру |
| Шторка | `addTransition` | `wipe-left/right/up/down`, направление из запроса |
| Ирис | `addTransition` | `iris`, duration по реестру |
| Плёночное зерно | `addEffect` | `film-grain`, диапазон внутри целевого клипа |
| Виньетка | `addEffect` | `vignette`, диапазон внутри целевого клипа |
| Slow Motion | `setSpeed` | 0.1 ≤ rate < 1; sourceFPS × rate ≥ timelineFPS |
| Fast Motion | `setSpeed` | 1 < rate ≤ 8 |
| Freeze Frame | `freezeFrame` | duration 0.25…30 секунд; существующий кадр из середины фрагмента |

`trim` и `setTransition(cut)` оставлены в типизированном словаре для развития, но ни одна применимая карточка этой редакции их не разрешает. Новых визуальных эффектов и генерации видео не добавлено.

`CinematicKnowledgeBase` загружает локальный JSON, проверяет схему и ID, подбирает до 3 карточек для контекста режиссёра (общий API ограничен 6). Контекст явно помечен как знания, а не наблюдения исходников. Карточка не является инструкцией, пришедшей с сайта. Данные о кадрах, хэшах, диапазонах, звуке и блокировках проверяются отдельно.

`NaturalLanguageDirector` перехватывает явные именованные запросы до общего парсера. Для недоступного приёма возвращается причина без подмены похожим эффектом. Упоминание «интервью» в просьбе добавить титр не превращает просьбу в монтажный приём. Примеры: «Добавь наплыв между клипами», «Добавь шторку вправо между клипами», «Добавь виньетку» на выбранном клипе. Для изменения одной границы нужны оба соседних клипа внутри разрешённой области.

Начальный обработчик именованных запросов применяет безопасные значения по умолчанию. Составные запросы, несколько приёмов и явные числа возвращают отказ с объяснением: произвольные числовые требования не заменяются молча значениями по умолчанию. Низкоуровневый `CinematicEditingPlan` имеет точные числовые параметры; его проверка независима от текста подсказки модели.

Перед исполнением целиком проверяются проект/таймлайн, статус карточки, разрешённая команда и стиль, реальные цели, область правки, границы исходника и эффекта, конечность и диапазоны чисел, точный набор параметров, повторные команды и соседство. Учитываются «Без эффектов», блокировки, исходный звук, подтверждённая речь, FPS, сложное изменение скорости и фиксированный хронометраж. Переходы не могут сдвинуть время воспроизведения заблокированного последующего клипа. При отказе исполнителя или AI-бюджета возвращается исходный таймлайн без частично сохранённых правок и без фиктивных квитанций выполнения.

Изменение времени допускается только без исходной аудиодорожки либо с явно отключённым звуком клипа; отсутствие ASR не считается отсутствием речи. Оптический переход также перекрывает звук: у обоих соседних клипов этой редакции нужны отключённый исходный звук или отсутствие аудиодорожек. Для смысловых и композиционных решений автоматические команды закрыты: общие теги и один кадр не подтверждают соответствие пары или развитие действия.

## Применение после анкеты режиссёра

Последний ответ анкеты теперь запускает создание первого фильма через обычный `AppModel.createFilm()`. Дополнительное нажатие «Создать фильм» не требуется. Готовые типизированные ответы сразу становятся брифом: языковая модель не вызывается для их повторного толкования. Если в поле ввода есть свободное пожелание, оно сохраняет обычную обработку режиссёром. При отсутствии доступного медиа бриф остаётся в поле для последующего запуска; занятая операция или уже существующий фильм не запускаются заново.

Ответы «Киношное настроение» и «Эффекты: Нормально/Много» подключают `CinematicAutomaticStyling` к обычному `TimelineComposer`. Отдельная команда «добавь зерно» не требуется. Политика выбирает только два применимых навыка: лёгкое `film-grain` на стабильном, достаточно экспонированном материале с низким измеренным шумом и `vignette`, когда наблюдения объектов покрывают начало/середину/конец диапазона и все наблюдаемые объекты остаются в центральной безопасной области. Для виньетки дополнительно требуется сохранённый fit без поворота и перекадрирования, а исходный диапазон должен совпадать с проверенным кандидатом: после подрезки его наблюдения не переносятся автоматически на новую выборку. Это ограниченные наблюдения, а не гарантия положения каждого невидимого объекта.

Проверяются хэш исходника, версия глубокого анализа, доступность исходника, диапазон кандидата, блокировки, качество и речь. Числовые пороги качества — консервативная политика продукта, не измеренная вероятность художественного успеха. База должна разрешать настоящий ID эффекта, а каталог — его просмотр и рендер. Количество акцентов остаётся в существующем бюджете: до 2/мин для «Нормально» или 6/мин для «Много», с дополнительным ограничением доли клипов и расстояния между акцентами. Никаких новых склеек, замедлений, стоп-кадров или изменений исходного звука этот автоматический слой не добавляет. Остальные проверенные именованные операции сохраняют прежний отдельный контракт.

Если подходящих новых наблюдений нет, сохраняется прежний выбор эффекта редактора; он не объявляется новым доказанным знанием. «Без эффектов» имеет приоритет. Старые проекты без выбора уровня эффектов сохраняют прежнее поведение. Автоматическая финальная сборка пересчитывает только созданные ею акценты под итоговые клипы; ручные эффекты сохраняются. Стабильные идентификаторы предотвращают ложное изменение подписи рендера при повторном проходе. Обычные локальные правки этот декоратор не вызывают.

`knowledgeAutomaticAvailable` в экспорте каталога отдельно показывает эту узкую автоматическую возможность. `knowledgeAIAvailable` по-прежнему обозначает допустимость проверенного именованного запроса и не обещает автоматического применения каждого пресета. Другие существующие политики VeloEdit используют собственные проверки настоящего каталога. Карточки не создают отсутствующих инструментов.

## Скорость, размер и дальнейшее обучение

Карточки и имена реестра нормализуются один раз; запрос работает по индексу. Контекст модели ограничен тремя карточками и 1024 байтами JSON, без нерелевантной вставки. Менее релевантные карточки удаляются целиком; определения для подсказки сокращены, а исполнитель использует полный оригинал карточки. Выбор приёмов выполняется по уже сохранённым наблюдениям, без нового прохода Vision/ASR/VLM, загрузок, новых вариантов монтажа или дополнительных вызовов языковой модели. Реальная стоимость эффекта при экспорте и prefill модели проверяются отдельно от времени поиска.

Начальный аудит полного bundle: 1,573 ГБ (1,465 GiB). Основные компоненты: речь — 602,8 MiB, Ollama — 482,9 MiB, исполняемые файлы — 167,8 MiB, FFmpeg — 108,3 MiB, музыка — 78,7 MiB, фоны — 44,0 MiB. Знания — 0,59 MiB. Две версии Metal/MLX внутри Ollama входят в поставляемый runtime и проверяются как разные совместимые backend-группы; это не две случайно забытые загрузки одной модели. Найдены только три служебных `.DS_Store`; сборка удаляет их, сохраняя модели, runtime, лицензии и соответствующий исходный код.

Практический вывод по текущему коду: расширять применение проверенных знаний полезно, но переобучение языковой модели пока не устраняет главный пробел — нехватку достоверных локальных наблюдений пары кадров и фаз действия. Приоритет: улучшить эти измерения, накопить реальные примеры удачных/неудачных решений и проверять новые правила на отдельной выборке. Уже существующий локальный профиль вкуса и обученный ранжировщик монтажных решений продолжают работать; копирование описаний киноприёмов не является дополнительным обучением их весов. Для SFT нужен подготовленный набор целевых примеров и отдельная оценка — см. [официальный SFT Trainer](https://huggingface.co/docs/trl/main/sft_trainer). Рекомендация отложить SFT здесь — инженерный вывод по состоянию VeloEdit, а не универсальное правило против дообучения.

Воспроизводимые проверки:

```sh
VELOEDIT_CINEMATIC_PERFORMANCE_OUTPUT="$PWD/Local/Reports/cinematic-performance.json" \
VELOEDIT_CINEMATIC_MEDIA='/path/to/test-media' \
./Scripts/dev-test.sh --jobs 2 --filter 'CinematicKnowledgeTests|CinematicAutomaticStylingTests|CinematicPerformanceTests|DirectorEffectsPolicyTests'
python3 Scripts/Tools/audit-app-footprint.py Build/VeloEdit.app --output Local/Reports/cinematic-footprint.json
```

Поиск сравнивается с исходным алгоритмом в одном процессе и проверяется на совпадение результатов. Рендер сравнивается на одинаковых исходных диапазонах, качестве и кодировщике с чередованием порядка; отдельно проверяются длительность и совпадение preview/MP4. Контролируемые оценки кандидатов в рендерном тесте не выдаются за новую разметку содержания исходника. Эти замеры не являются обещанием времени полного первичного анализа произвольного архива. Фактические результаты дополнения записываются в [отчёт](test-report.md).

## Инвентаризация и обновление

Экспорт актуальных 62 эффектов, 48 переходов, их параметров, диапазонов, значений по умолчанию, keyframes, доступности для базы и проверочных тестов:

```sh
Build/veloedit-cli cinematic-catalog /tmp/veloedit-capabilities.json
python3 Scripts/Tools/audit-director-operations.py
```

Поля `previewDeclared` / `exportDeclared` означают декларацию каталога. Поле `verification` указывает конкретный тест; фактические результаты записаны отдельно. `applicationAIAdvertised` означает наличие названия в словаре ИИ, а разрешение этой базы задаётся только `knowledgeAIAvailable` и allowlist карточки. Проверенные примеры не означают сертификацию каждого сочетания параметров.

Обновление источника выполняется только явно, отдельно от приложения:

```sh
python3 Scripts/Tools/refresh-cinematic-sources.py --output /tmp/veloedit-cinematic-extraction.json
python3 Scripts/Tools/curate-cinematic-knowledge.py --extraction /tmp/veloedit-cinematic-extraction.json
```

Первый скрипт сохраняет отобранный текст во временный файл, без медиа и HTML. Существующий output возобновляет прежнюю выгрузку; для полного обновления нужен новый путь либо удаление прежнего временного файла. Второй использует авторскую русскую редакцию; он не создаёт качественные новые карточки автоматически. Для новой редакции нужно пересмотреть даты, перечень/обоснования, словарь, примеры и результаты испытаний. Временную выгрузку не следует включать в дистрибутив. После изменения ресурсов обязательна полная сборка `./Scripts/build-app.sh`.
