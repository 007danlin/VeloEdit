# ТЗ База киноприёмов для режиссёра VeloEdit

Дата: 9 октября 2026 года. Статус: требования к реализации.

Подготовить локальную базу знаний, которая помогает режиссёру понимать снятый материал, выбирать кадры и выполнять монтаж существующими средствами VeloEdit. Любое исполняемое действие должно соответствовать доступной команде, эффекту или переходу приложения.

Источник материала — [каталог Cinematic Techniques на Melies](https://melies.co/cinematic-techniques). Сайт используется при подготовке базы: нужную информацию отбирают, перерабатывают и сохраняют локально. Во время работы режиссёр обращается к сохранённым знаниям; доступ к сайту и интернету для этой функции не требуется. Обновление базы выполняется отдельно и явно.

## Перечень возможностей VeloEdit

Составить актуальный перечень монтажных операций, эффектов, переходов и средств анализа кадров. Для каждого действия указать ID, доступные параметры, допустимые диапазоны, ограничения и доступность для ИИ. Проверить фактическое выполнение, предпросмотр и экспорт: наличие названия в коде не подтверждает работоспособность.

Основные точки проверки:

- `Sources/VeloEditCore/AIDirectorEngine.swift` — команды и их исполнение.
- `Sources/VeloEditCore/TransitionEffectCatalog.swift` — каталоги и параметры эффектов и переходов.
- `Sources/VeloEditCore/TimelineObjects.swift` — типы объектов таймлайна.
- Действующие средства анализа медиа — какие признаки кадра и действия они действительно возвращают, с какой временной точностью и уверенностью.

## Аудит материала сайта

Просмотреть все разделы и карточки каталога. Для каждого приёма сохранить название, ссылку, решение об использовании и его обоснование.

| Статус | Основание |
| --- | --- |
| Применим | Приём выполняется проверенными инструментами VeloEdit при наличии подходящих исходников |
| Полезен для анализа | Помогает распознавать, оценивать или выбирать существующие кадры |
| Отложен | Требует отсутствующей функции либо признаков, которые текущий анализ не определяет надёжно |
| Исключён | Относится к генерации материала или не приносит пользы нашим монтажным задачам |

Один приём может содержать полезные знания для анализа, даже если его создание недоступно. Не исключать такие знания только из-за отсутствия одноимённого эффекта.

Подробную подготовку начать с **Editing and Transitions**, **Framing and Shot Size** и **Composition**. Из остальных разделов брать материал по результатам сопоставления с возможностями приложения. Новые эффекты и генерация видео в этот этап не входят.

## Отбор информации

Для выбранных приёмов сохранить определения, признаки в кадре, назначение, условия применения, противопоказания, типичные ошибки и способы проверки результата. Добавить русские формулировки и английские названия для поиска.

Убрать рекламу, генеративные промпты и повторы. Из примеров извлекать полезное правило и объяснение; не сохранять целые страницы без отбора. Иллюстрации включать только при наличии конкретной задачи распознавания и разметки. Для каждой карточки сохранять ссылку на источник и дату извлечения.

Авторские трактовки и рекомендации источника не превращать в безусловные правила монтажа. Учитывать замысел пользователя и содержание исходников.

## Структура локальных знаний

Каждая карточка должна содержать:

- ID, название, категорию, источник и статус применимости.
- Цель приёма и признаки, по которым его можно распознать.
- Необходимые данные об исходниках, условия применения и ограничения уверенности.
- Разрешённые команды и ID из каталога VeloEdit, параметры и порядок действий.
- Условия отказа, положительный пример, неподходящий пример и способ проверки результата.

Для знаний, используемых только при анализе, список исполняемых команд может быть пустым.

Монтажный приём не обязательно является эффектом. Например, match cut описывать через подбор подходящих фрагментов, их обрезку и прямую склейку. Не создавать вымышленный эффект с таким названием. Возможность применить приём зависит и от наличия инструментов, и от подтверждённого соответствия исходников.

## Использование режиссёром

На первом этапе использовать локальную базу без переобучения модели. Для запроса подбирать небольшой набор подходящих карточек с учётом задачи, фактов о материале и доступных инструментов.

Режиссёр формирует структурированный план только из разрешённых действий. До изменения таймлайна программно проверять ID, параметры, существование целевых клипов, временные границы и условия применимости. Ограничение одним текстовым запретом в промпте недостаточно.

Если данных, исходников или уверенности не хватает, пропустить приём и указать причину. Не подменять недоступный приём другим эффектом без основания в запросе. Соблюдать область правки, блокировки и настройки пользователя, включая «Без эффектов».

Знания о крупности, композиции или движении сами по себе не добавляют зрительных возможностей модели. Для конкретного решения требуются наблюдения, привязанные к исходнику и времени. Один описанный кадр не подтверждает последовательность действий.

## Проверка и критерии приёмки

Проверить систему на размеченных исходниках: подходящие случаи, неподходящий материал, неполный анализ и запросы отсутствующих эффектов. Для каждого сценария задать ожидаемое действие или отказ, затем проверить изменения таймлайна и экспортированный результат.

Приёмка требует следующего:

- Каждый включённый приём имеет источник, статус и обоснование применимости.
- Все исполняемые действия связаны с проверенными возможностями приложения.
- Неизвестные ID и недопустимые параметры отклоняются до изменения таймлайна; выполненных несуществующих действий — ноль.
- Решения подтверждаются данными конкретных исходников; неподтверждённые признаки не выдаются за факты.
- Сохраняются смысл сцены, целостность речи и ограничения пользователя.
- Работа базы проверена без доступа к сайту и интернету.
- После изменений исходного кода или ресурсов приложения выполнена полная сборка `./Scripts/build-app.sh` согласно инструкциям проекта.

## Результаты работы

Предоставить реестр рассмотренных приёмов с решениями «берём / откладываем / исключаем», карту соответствий инструментам VeloEdit, локальную базу карточек и проверочные примеры с результатами. Отдельно перечислить полезные знания, применение которых пока ограничено возможностями анализа кадров.
