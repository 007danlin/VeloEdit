**01. Требование владельца продукта и приоритет документа**

Пользователь хочет приложение, в котором он выбирает материалы, при желании описывает фильм и нажимает кнопку. Приложение самостоятельно доводит работу до проверенного результата. Пользователь не должен управлять анализом, перезапускать модели, пересоздавать прокси, разбирать ошибки проверки, повторять экспорт или решать технические проблемы монтажа.

Отчёт используется как перечень проблем и свидетельств. Его предложения о дополнительных предупреждениях, мастерах, кнопках повторения и объяснениях не являются обязательным способом решения. Настоящее ТЗ перерабатывает их в автоматические действия приложения. При противоречии с рекомендацией из отчёта приоритет имеет требование владельца об автономности и конкретный контракт настоящего ТЗ.

Все пункты ниже предназначены исполнителю будущей реализации. Создание этого ТЗ само по себе не разрешает считать функции реализованными, изменять исходные пользовательские проекты или публиковать приложение.

**02. Продуктовый результат**

Обычный путь состоит из осмысленных пользовательских действий: выбрать материалы → нажать «Создать фильм» → посмотреть фильм. Пожелание необязательно. Сохранение готового видео запускается одной кнопкой «Сохранить видео». Дополнительные параметры доступны по желанию и не являются условием работы.

После «Создать фильм» приложение само проверяет готовность среды, принимает материалы, анализирует необходимое, собирает историю, оформляет её, исправляет обнаруженные недостатки, проверяет итоговую композицию и сохраняет доступный для просмотра монтаж. Отдельные обязательные кнопки «Анализировать», «Проверить», «Исправить», «Продолжить сборку» из обычного пути исключаются. Расширенные инструменты остаются доступными.

После «Сохранить видео» приложение само выбирает параметры по действующим настройкам проекта, проверяет ресурсы и зависимости, создаёт файл, проверяет его и оставляет постоянную карточку результата. По умолчанию файл сохраняется в доступную папку экспорта проекта под уникальным именем. «Сохранить как…» позволяет выбрать другое место; выбранное пользователем место нельзя молча подменять.

Создание фильма означает сохранённый монтаж и рабочий просмотр. Экспорт означает отдельно проверенный конечный файл. Эти результаты нельзя смешивать. Если предусмотрена команда «Создать и сохранить», она выполняет оба действия в одном задании.

**03. Неизменяемые правила автономности**

| Правило | Обязательное поведение |
| --- | --- |
| Восстановимые технические сбои | Исправлять внутри текущего задания без диалога и повторного нажатия пользователем |
| Сохранность | Сохранять последнюю рабочую версию и последнюю пользовательскую правку до публикации новой версии |
| Требования пользователя | Не ослаблять явно заданные длительность, формат, обязательные сцены, музыку, звук и ограничения ради успешной проверки |
| Качество | Исправлять дефект результата; не отключать проверку и не подменять её фиктивным успехом |
| Резервная обработка | Разрешена при сохранении функционального и качественного контракта; выбранный путь записывать в локальную диагностику |
| Ручная работа | Автоматизация не отменяет ручное выделение, закрепление, правки и отмену операции |
| Диагностика | Подробный локальный журнал доступен по запросу; технические сообщения не засоряют чат и основной экран |
| Вопросы | Только необходимое внешнее действие или реальное противоречие обязательных требований, которое нельзя разрешить из контекста |
| Повторные попытки | Ограничены, отменяемы, учитывают уже выполненную работу; одинаковый отказ не запускает бесконечный цикл |
| Честный результат | Наличие старого плеера, записанного файла или короткого черновика не означает выполнения нового задания |

Разумные настройки выбираются приложением. Не требуется спрашивать про режим модели, количество проходов анализа, способ декодирования, размер технических прокси, повтор проверки, очистку безопасного кэша или способ ремонта композиции.

Автономность не даёт разрешения удалять оригиналы, пользовательские экспорты, сохранённые версии и чужие модели; менять системную безопасность; покупать услуги; отправлять материалы в облако. Обычные системные разрешения запрашиваются тогда, когда они необходимы, и затем используются повторно в пределах предоставленного доступа.

**04. Что считается готовностью**

Для фильма `ready` разрешён только при одновременном выполнении следующих условий:

1. Результат соответствует актуальному заданию, включая явно заданные обязательные требования.
2. Проверена фактически построенная композиция с её титрами, звуком, переходами и прочими слоями.
3. Результат и его зависимости сохранены; повторное открытие возвращает ту же версию.
4. Просмотр подготовлен и способен показать актуальный фильм.
5. Результат опубликован для текущей ревизии проекта; более поздние изменения пользователя не затёрты.

Для экспорта дополнительно обязательны существующий завершённый файл, повторное открытие медиаконтейнера, проверка параметров и длительности, декодирование контрольных точек изображения и звука. Проверка относится к подписи именно этого результата. Изменение входов делает зависимую проверку недействительной.

Субъективные предпочтения и технические блокирующие нарушения хранятся раздельно. Оценка вкуса сама по себе не должна обнулять технически исправный и соответствующий заданию фильм. В то же время независимая проверка результата не заменяется самооценкой планировщика. Обязательные проверки нельзя сделать необязательными только потому, что они не прошли.

Если точная длительность, конкретный трек или обязательная сцена объективно недоступны, сохраняется черновик, а задание не получает `ready`. Перед таким решением приложение должно выполнить предусмотренные поиск и восстановление. Нужное действие пользователя показывается один раз. Для свободного задания приложение само выбирает достижимую длительность и допустимое оформление без согласования.

**06. Единое устойчивое задание**

Ввести либо расширить сохраняемую запись задания. Минимальные поля: ID, вид действия, ID проекта, актуальный intent, базовая ревизия и подпись зависимостей, текущий этап, состояние, завершённые артефакты, результаты их проверки, история восстановления, бюджеты повторов, блокирующая внешняя зависимость, признак явной отмены, версия схемы и исполнитель.

Состояния: ожидает выполнения; выполняется; автоматически восстанавливается; ожидает внешнего условия; приостановлено пользователем; отменено пользователем; завершено; остановлено из-за внутреннего невосстановленного отказа. Этапы — подготовка среды, импорт, анализ, планирование, сборка, проверка и ремонт, подготовка просмотра, фиксация, экспорт. Состояние и этап не смешивать.

Один проект имеет одного владельца изменяющей операции. Параллельные независимые вычисления допустимы внутри задания с ограничением ресурсов. Повторный клик, перезапуск приложения и повтор доставки события не создают дублирующий импорт, фильм или экспорт. Для явной команды «Переделать» создаётся новая версия.

Каждый дорогой завершённый этап сохраняет проверяемый артефакт. После сбоя повторяется ближайшая незавершённая зависимая работа. Частичный файл не считается артефактом; наличие пути на диске недостаточно. Использовать подписи входов и версий алгоритмов, проверку целостности и атомарную публикацию.

После непреднамеренного прерывания совместимое задание автоматически продолжается при открытии соответствующего проекта. Отдельное нажатие «Продолжить» не требуется. Явно отменённое или приостановленное пользователем задание само не возобновляется. Не запускать одновременно тяжёлую обработку всех недавних проектов. После изменения намерения переиспользуются только совместимые этапы; устаревшие результаты не публикуются.

**07. Политика автоматического восстановления**

Каждый сбой классифицируется по причине, зависимости и способу ремонта. Строка `localizedDescription` не является контрактом принятия решения. Для старых ошибок нужен адаптер к типизированной классификации.

| Класс ситуации | Последовательность действий приложения | Когда разрешено обратиться к пользователю |
| --- | --- | --- |
| Краткий сетевой отказ | Повтор с ограниченной задержкой, другой допустимый провайдер, подходящая локальная библиотека | Нужен конкретный отсутствующий ресурс без допустимой локальной замены |
| AI-сервис не отвечает | Проверить работоспособность, перезапустить принадлежащий приложению сервис, восстановить сессию, использовать совместимый доступный путь | Нужно разрешение или установка ресурса, которые нельзя выполнить в рамках уже данных разрешений |
| Повреждённый кэш | Проверить оригинал, удалить только повреждённый восстанавливаемый артефакт, пересоздать | Оригинал тоже недоступен и не найден |
| Сбой декодирования | Повторное открытие, другой поддерживаемый путь чтения, производная копия из оригинала, использование исправных диапазонов | Нет читаемого материала для обязательного требования |
| Ошибка проверки монтажа | Локально исправить причину, пересобрать затронутые зависимости, проверить заново | Только если требование физически невыполнимо имеющимся материалом |
| Несовпадение ревизий | Загрузить актуальное состояние, переосновать совместимую операцию, повторить зависимые этапы | Реально противоречащие обязательные изменения, для которых нет безопасного порядка |
| Ошибка записи | Повтор, безопасный локальный журнал восстановления, последующая синхронизация | Нельзя создать ни основную, ни резервную долговечную запись |
| Дефицит места | Освободить разрешённый неиспользуемый кэш, пересчитать бюджет, продолжить | Нужно освободить пользовательские данные или выбрать другой диск |
| Нагрев/давление памяти | Уменьшить параллелизм и рабочие наборы, дождаться нормальных условий | Пользователь не нужен; состояние ожидания ресурса отражается спокойно |
| Прерывание экспорта | Переиспользовать завершённые зависимости, заново выполнить незавершённую фазу с тем же контрактом | Место назначения либо оригиналы физически недоступны |

Начальные ограничения политики: до двух повторов одного временного отказа после первой попытки; базовые задержки 1 и 3 секунды с учётом отмены и подсказки сервиса. Следующая попытка того же детерминированного отказа обязана менять стратегию. Отпечаток попытки включает тип причины, входы, стратегию и версию алгоритма. Перезапуск приложения не обнуляет бюджеты.

Для ремонта одной композиции разрешить до шести изменяющих её циклов, включая финальный консервативный вариант. Не умножать этот предел скрытыми вложенными retry. Дорогие операции имеют общий бюджет этапа и общий бюджет восстановления задания; начальные значения рассчитываются по объёму работы и профилю устройства, фиксируются до попытки и покрываются тестами. Длительность обычного анализа большого архива не считать ошибкой только из-за длинного времени.

Каждый этап передаёт фактическое продвижение либо состояние ожидания ресурса. Watchdog различает работающий длительный этап, ожидание охлаждения, временную сеть и зависший процесс. Ожидание ресурса не расходует счётчик неудачных попыток, но не выдаётся за выполняющуюся обработку. Недоступный диск не опрашивается в горячем цикле: использовать уведомления о подключении и редкие ограниченные проверки.

Внутренний отказ после исчерпания всех допустимых стратегий сохраняет последнюю рабочую версию и диагностический пакет. Пользователю не предлагается чинить код, сбрасывать кэш или искать модель вручную. Одна спокойная запись о незавершённом задании допустима; успех не имитируется. Такой исход в обязательном испытательном сценарии означает непринятую реализацию.

**08. A01 — сохранение, аварийная копия и выход**

Обеспечить долговечность пользовательских правок независимо от длительной сериализации, AI и рендера. Использовать основной атомарный commit и компактный журнал операций либо совместимый механизм восстановления. Не размножать полный тяжёлый manifest на каждое движение курсора.

Если основной пакет временно недоступен, автоматически сохранять необходимые для восстановления изменения в управляемом локальном хранилище приложения. Перед разрешением выхода проверить, что такая запись действительно существует и читается. При следующем открытии автоматически восстановить изменения в правильный проект с проверкой ID и ревизий. Статус «Сохранено в проект» нельзя показывать, если изменения пока находятся только в аварийной копии.

При конфликте другого процесса переиграть безопасно совместимые операции поверх актуальной версии. Не отключать CAS и межпроцессную блокировку. Несовместимую версию сохранить отдельно для восстановления; не перезаписывать чужую актуальную работу. Если невозможно сохранить ни одну долговечную копию, выход не разрешать автоматически: требуется одно реальное действие по выбору доступного места.

Приёмка A01: отказ записи в основной пакет → правка остаётся в локальном журнале → выход и повторный запуск → та же правка восстановлена без ручной команды. При недоступности всех мест хранения приложение не сообщает об успешном сохранении и не теряет последнее состояние.

**09. A02 — материалы: самостоятельный поиск, импорт и восстановление**

После выбора папки приложение автоматически обнаруживает поддерживаемые видео, фото, звук и телеметрию, устраняет дубли, создаёт миниатюры и строит карту источников. При повреждении миниатюры импорт исходника не проваливается. При повторном добавлении того же набора без новых данных не запускать полную пересборку фильма.

Автоматический поиск потерянного файла: сохранённый bookmark и файловая идентичность → известное размещение тома → прежняя родительская папка → другие уже разрешённые папки проекта. Не обходить безгранично весь компьютер. Совпадение только по имени недостаточно; использовать доступные размер, длительность, отпечатки и другие признаки. Неоднозначную замену не выбирать наугад.

Если один файл повреждён, попытаться использовать читаемые диапазоны и другие материалы, сохраняя обязательные требования. Не молча исключать обязательное событие, явно выбранный трек или закреплённый фрагмент. Подробный поимённый итог доступен в медиатеке по запросу; успешный импорт не заканчивается обязательным просмотром отчёта ошибок.

Приёмка A02: перемещение папки в разрешённых пределах восстанавливается автоматически; дубликаты не создают лишних клипов; один повреждённый необязательный файл не блокирует фильм, если оставшийся материал удовлетворяет контракту; отсутствующий обязательный источник вызывает только запрос нужного файла или диска.

**10. A03 — готовность локального AI**

Приложение отвечает за работоспособность поддерживаемого локального runtime. Обычный пользователь не обязан устанавливать Homebrew, запускать терминал и команды `ollama serve/pull`. Исполнитель должен обеспечить поставку совместимого runtime с приложением либо управляемую установку из доверенного источника с проверкой версии и целостности. Сохранить необходимые системные подтверждения и условия распространения.

При первом запуске выбрать подходящий устройству профиль и подготовить минимальный поддерживаемый набор. Единственное предварительное подтверждение загрузки допустимо, если оно действительно необходимо; показать объём. Возобновлять прерванную загрузку, проверять результат, запускать сервис и прогревать требуемую модель автоматически. Не скачивать большие модели без потребности и разрешения на соответствующую загрузку.

После подготовки приложение должно выполнять основной сценарий без интернета. Перезапускать автоматически можно только сервис, которым управляет VeloEdit; чужой процесс нельзя завершать на основании одного совпадения порта. Резервная модель или алгоритм допускаются, если проходят тот же контракт результата. Нельзя объявить глубокий анализ выполненным, когда фактически получены только метаданные.

Приёмка A03: чистая поддерживаемая установка доводится до готовности средствами приложения; остановка управляемого сервиса во время работы восстанавливается; после подготовки офлайн-сборка проходит без установочных команд и выбора моделей пользователем.

**11. A04 — анализ и длительность под задачу**

Пользователь не управляет количеством кандидатов и проходов анализа. Приложение начинает с достаточного базового анализа, затем углубляет только необходимые области. Если текущий набор кандидатов не покрывает задание, автоматически расширять поиск по ранее не рассмотренным исходникам и диапазонам. Малый внутренний shortlist не является доказательством отсутствия материала.

Различать три режима длительности: автоматическая при отсутствии требования; приблизительная при формулировке «около»; точная при явном точном значении. Для точного режима допустимо расхождение не больше одного кадра конечной композиции, включая перекрытия переходов. Для приблизительного режима начальный допуск — 5% от цели, если пользователь не задал свой диапазон. Явно заданный диапазон имеет приоритет. Не превращать приблизительное пожелание в обязательный вопрос.

До решения о нехватке материала обязателен базовый просмотр всех доступных визуальных исходников, выявление технически пригодных диапазонов и углубление областей, способных устранить недобор. Отдельно фиксировать необследованные области: их наличие исключает вывод «материала больше нет». При этом нельзя пытаться анализировать каждую секунду архива с максимальной моделью независимо от задачи.

Для набора длительности использовать новые пригодные моменты, продление внутри подтверждённого действия, естественный показ фото, полноту события и восстановление ошибочно отсеянных сцен. Запрещено набивать точную длительность повтором одинаковых кадров, пустыми вставками, незапрошенным замедлением, бесконечными фото или freeze-frame padding. Порядок событий и закреплённые фрагменты сохраняются.

Приёмка A04: сценарий «пять минут», где подходящих неповторяющихся диапазонов заведомо достаточно, заканчивается фильмом длительностью пять минут без обращения к пользователю. Исходный выбор на 43 секунды инициирует расширение анализа и ремонт. Объективно недостаточный набор не получает ложный `ready`; свободное задание на том же наборе автоматически получает достижимый полноценный результат.

**12. A05 — автоматический ремонт качества фильма**

Каждый блокирующий дефект должен иметь проверяемую стратегию исправления и точную область повторной проверки. Система использует уже существующее разделение планировщика, независимой проверки и ремонта.

| Дефект | Автоматическое исправление |
| --- | --- |
| Нечитаемый титр | Исправить контур, тень, подложку, размещение и допустимые параметры анимации; сохранить текст и обязательное оформление |
| Бессодержательный автоматический заголовок | Сформировать название по подтверждённому событию либо нейтральный достоверный вариант; не выдумывать место, имя и дату |
| Плохое кадрирование | Выбрать безопасную траекторию или полный fit; проверить реальное содержание кадра |
| Повторяющиеся соседние планы | Выбрать другой момент или изменить длительность плана; заново проверить появившееся соседство |
| Обрыв действия или реплики | Расширить границы в допустимом исходнике либо заменить момент; сохранить завершение действия |
| Неудачный переход | Исправить границы и перекрытие; для автоматически выбранного оформления использовать более простой подходящий переход или чистую склейку |
| Чёрный/недекодируемый кадр | Пересоздать зависимый артефакт или заменить допустимый исходный диапазон; намеренное затемнение не считать автоматически дефектом |
| Неудачная автоматическая музыка | Выбрать другой подходящий допустимый трек; исправить стык, длительность и окончание |
| Сбой одного автоматически выбранного эффекта | Исправить реализацию либо заменить допустимым эквивалентом; не трогать явно заданный эффект без сохранения его результата |

Ремонт конкретного титра не пересобирает всю историю. Изменение порядка кадров инвалидирует связанные тайминги, музыку и телеметрию. После удаления или замены сцены снова проверяется выполнение длительности и содержательных требований. Нельзя удалять обязательный заголовок, чтобы пройти OCR, или исключать главного героя ради формального улучшения оценки.

Резервная консервативная сборка использует исходники всего допустимого проверенного пула, а не только несколько ранее выбранных клипов. Она сохраняет требования к истории, длительности, музыке, титрам и ручным ограничениям. Консервативный результат — простое качественное оформление, а не разрешение потерять содержание.

Приёмка A05: намеренно внесённые дефекты из таблицы исправляются без сообщений вида «исправьте титры», «запустите проверку» или «уменьшите длительность». Проверяется реальный кадр после ремонта. Шесть неуспешных циклов не скрываются новым названием статуса и считаются провалом соответствующей приёмки.

**13. A06 — звук, музыка, титры и телеметрия без ручной технической настройки**

Сохранить действующие проверенные правила проекта и явно заданное оформление. До изменения defaults проверить [AutopilotDefaults.md](../Features/autopilot-defaults.md), соответствующие политики и регрессионные тесты. В частности, не добавлять без запроса декоративные фильтры, шумоподавление, эквалайзер и звуковые эффекты под видом повышения автономности. Зафиксированное поведение приглушения исходников до 20% должно сохраняться для embedded и detached звука и после экспорта; мастеринг не усиливает его обратно. Пользовательское числовое значение имеет приоритет.

Автоматический подбор музыки сам проходит допустимые источники и локальный резерв. Отключение одного каталога не становится пользовательской задачей. Выбранный конкретный трек не заменять произвольно. Для офлайн-сценария обеспечить поддерживаемую локальную библиотеку с сохранёнными условиями использования; не устанавливать одну универсальную композицию всем фильмам. Музыка заканчивается естественно и не обрывается на конце монтажа.

Сведения о музыке автоматически сохраняются с проектом и рядом с экспортом, когда они требуются по данным библиотеки. Сборка не останавливается с задачей «скопируйте атрибуцию». Неизвестное происхождение трека не считается проверенным разрешением. Если нужный трек требует отдельного пользовательского права или доступа, это внешняя зависимость.

Титры автоматически соответствуют событиям, имеют корректные подтверждённые даты, читаются и не накладываются друг на друга бессмысленно. Существующий принятый стиль сохраняется; ремонт контраста не даёт права произвольно менять шрифт и композицию. Не выдавать техническое имя файла или внутренний шаблон за название истории.

Телеметрия автоматически определяется, привязывается к соответствующему видео, синхронизируется и ограничивается интервалами фактических данных. Показывать только полезные подтверждённые показатели согласно заданию и сохранённым предпочтениям. Пустые или выдуманные значения запрещены. Если телеметрия не запрошена и достоверных данных нет, она просто не добавляется. Если запрошен конкретный отсутствующий показатель, действуют правила обязательного требования.

Приёмка A06: сбой музыкального провайдера не мешает свободному автоподбору; явно выбранная музыка сохраняется; исходный звук имеет запрошенный уровень в декодированном результате; титры читаются на светлых и тёмных участках; телеметрия совпадает со временем исходника после перестановок и подрезки.

**14. A07 — автономный экспорт с сохранением качества**

Предварительная проверка выполняется автоматически внутри команды сохранения. Исправимые проблемы устраняются там же; отдельный обязательный экран проверки отсутствует. Настройки по умолчанию определяются действующим контрактом проекта и экспортной политикой. Технические параметры доступны для просмотра и ручного изменения.

Резервный путь рендера должен сохранять выбранные размеры, FPS, временные метки, пропорции, звук и договорённое качество. Допустим другой способ кодирования при выполнении контракта. Запрещено молча экспортировать analysis/preview proxy вместо оригинала, уменьшать разрешение или FPS, убирать слои, выдавать другой контейнер под прежним расширением либо отключать проверку конечного файла.

Работать через staging-артефакт. Предыдущий экспорт остаётся целым до успешной проверки нового. Уникальное имя является стандартом; замена существующего файла выполняется только как осознанный пользовательский выбор. Незавершённый экспорт после запуска приложения автоматически восстанавливается из завершённых зависимостей; кодирование может начать незавершённую фазу заново, но не должно выдавать это за продолжение с последнего байта.

Оценка места учитывает диск назначения, место для промежуточных материалов, выбранный профиль, длительность и резерв. Сначала удаляется только разрешённый неиспользуемый кэш VeloEdit. Пользовательские экспорты, исходники, контрольные версии и используемые текущей композицией файлы не удаляются.

Для FCPXML автоматически готовить допустимые зависимые ресурсы и понятную папку передачи. Сохранение внешнего вида и возможность последующего редактирования параметров различаются. Отчёт о переносимости — необязательные для просмотра сведения рядом с результатом. Если пользователь явно требует редактируемый параметр, подмена его запечённым видео не считается выполнением требования.

Приёмка A07: прерывание кодирования и временный отказ штатного пути не требуют повторного нажатия экспорта; исправный файл появляется с первоначально выбранными параметрами. На экране остаются «Открыть видео» и «Показать в Finder». Открытие проекта позднее показывает экспорт и версию монтажа, из которой он получен.

**15. A08 — ручные правки, версии и удаление**

Простая команда должна изменять только запрошенную область. Для «замени музыку» по умолчанию сохраняются клипы, титры, длительность и ручные правки. Для выбранного диапазона его границы и привязка сохраняются в задании. Изменение таймлайна во время обработки требует автоматического безопасного переоснования команды либо отмены устаревшей зависимой работы.

Перед значимой автоматической или ручной операцией сохраняется контрольная версия. История доступна для просмотра и возврата по желанию пользователя; она не является обязательным этапом принятия каждого результата. Восстановление старой версии сохраняет текущую и не запускает самопроизвольное повторное применение отменённой AI-команды.

Удаление материала из проекта должно быть обратимой операцией проекта с сохранением зависимостей, а не только удалением клипа из активного таймлайна. Пользовательские оригиналы остаются нетронутыми. Не создавать множество подтверждений для обычных обратимых правок; последствия массовой операции должны быть ясны из самого действия, а восстановление — доступно.

Приёмка A08: параллельная ручная подрезка переживает завершение AI-задачи; локальная команда не выходит за диапазон; Undo и восстановление версии возвращают нужное состояние; удаление и возврат источника восстанавливают его анализ, клипы и зависимые слои.

**16. A09 — ресурсами управляет приложение**

Использовать существующие мониторинг и ограничители нагрузки. Размер рабочих наборов, количество одновременно открытых декодеров, число модельных запросов и проходы по архиву зависят от памяти, температуры и активной работы пользователя. Интерфейс и сохранение приоритетнее фоновой генерации.

Кэш имеет категории, учёт ссылок, версию формата и безопасное освобождение. В первую очередь удаляются устаревшие, повреждённые и неиспользуемые восстанавливаемые артефакты. Не удалять последнее средство восстановления задания или файл, который ещё читает плеер. После очистки необходимые данные создаются автоматически без отдельного режима ремонта.

Ограничение ресурсов не разрешает скрыто ухудшать экспорт или не выполнять семантическое задание. Изменение глубины анализа допускается только если результат всё равно проходит контракт. Не запускать всю обработку заново из-за обновления одного титра или открытия панели.

Приёмка A09: управление окном и правки остаются отзывчивыми во время обработки; после моделируемого перегрева работа продолжается сама; кэш восстанавливается; одновременно открытые проекты и повторные клики не запускают конкурирующие тяжёлые задания на один результат.

**17. A10 — простой интерфейс готового результата**

Основной интерфейс показывает действие, прогресс и результат. Во время работы допустимы короткие состояния «Готовлю материалы», «Собираю фильм», «Проверяю результат», «Сохраняю видео». Восстановление обычного технического сбоя остаётся частью работы. Сообщения «провайдер недоступен», «повторяю запрос модели», `coverage`, `CAS`, `OCR`, `fallback` не выводятся в чат.

Главная открытого проекта показывает последний фильм и одну подходящую кнопку продолжения обычной работы. После успешной сборки просмотр заметнее переписки. Выбор модели, расширенная медиатека, инспекторы, лицензии, журнал и история версий доступны, но не мешают получить результат.

Автоматически выбирать удачную компоновку для размера окна; сохранять пользовательские размеры панелей и положение окна. Скрытие боковой панели не скрывает единственный индикатор текущей работы. Доступны понятный клавиатурный фокус, различимые имена элементов и русские подписи. Длительности имеют единое округление и точный формат в инструментах монтажа.

Медиатека автоматически группирует исходники по подтверждённым событиям и времени; доступны поиск, фильтры, множественный выбор и компактный список. Обзор анализа и альтернативные моменты открываются по желанию. Предпросмотр оригинала, выбор его начала/конца и добавление диапазона в фильм — различимые действия. Подсказка о выборе клипа размещается рядом с инструментами и не является диалогом ошибки. Для запрошенных субтитров обеспечить автоматическую расшифровку и синхронизацию с возможностью исправить текст.

Необходимый пользовательский ввод ограничивается выбором материалов, явным творческим пожеланием, нужным системным разрешением и объективно отсутствующим ресурсом. Проактивный длинный опрос о формате, настроении, модели, переходах и музыке не допускается. Если параметры не указаны, применять существующие разумные настройки и предпочтения.

Приёмка A10: подготовленный пользователь нажимает «Создать фильм» один раз и получает результат без обязательных промежуточных диалогов. Восстановимые сбои не увеличивают число его действий. Расширенные функции остаются доступны через интерфейс и клавиатуру.

**18. A11 — перенос проекта, обучение, поддержка и поставка**

«Собрать копию проекта» выполняет упаковку материалов, музыки и других необходимых зависимостей автоматически: выбирает безопасное имя, оценивает место, копирует и проверяет итог. Технические ошибки копирования восстанавливаются в пределах общего задания. Оригинальный проект не меняется. Исключения из состава копии — только осознанный выбор пользователя.

Профиль вкуса должен помогать принимать настройки по умолчанию. Не обучаться на аварийном сокращении, вынужденном техническом резерве, неподтверждённом результате или собственном выборе алгоритма как будто это одобрение пользователя. Явное исправление имеет больший вес. Просмотр, сброс и приостановка обучения доступны в настройках.

Диагностический пакет создаётся локально автоматически при невосстановленном внутреннем сбое: идентификатор задания, версия приложения, входные сигнатуры, этап, попытки и причины, результаты проверки. Личные пути и названия можно скрыть при экспорте. Диагностика не отправляется без решения пользователя и не требуется для обычного продолжения работы.

У каждой сборки должны быть однозначный номер, дата и идентификатор исходников. Отдельные тестовые копии различимы. Проверить открытие `.veloedit` из Finder, миграцию с резервной копией, запуск установленного пакета и сохранение пользовательских настроек окна. Обновление версии приложения не запускает без необходимости новую генерацию исправных проектов.

Приёмка A11: упакованная копия работает при недоступных первоначальных путях; технический fallback не искажает профиль вкуса; диагностика показывает точную сборку; двойной щелчок по проекту открывает нужную установленную версию.

Целевой итог: после одного осмысленного действия пользователя VeloEdit сам выполняет техническую работу, исправляет предусмотренные восстановимые сбои и отдаёт проверенный результат. Пользователь занимается содержанием фильма.
