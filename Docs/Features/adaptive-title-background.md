# Адаптивная читаемость титров

Титр сам по себе не включает размытие. На читаемом фоне адаптивная обработка возвращает исходное изображение без изменений. Анализ и отрисовка выполняются локально, без внешнего AI-сервиса.

## Обработка

1. Core Text определяет фактические границы каждой строки после переноса, подбора шрифта, изменения положения, масштаба и поворота.
2. Область каждой строки анализируется отдельно: яркость в линейном пространстве, контраст с цветами текста (включая выделенное слово), доля недостаточно контрастных участков и плотность мелких деталей. Учитываются размер текста, число строк, длина строки и прозрачность.
3. Применяется минимальная ступень: исходный кадр → контур/тень → мягкое локальное затемнение → более плотная полупрозрачная область → локальное размытие. Для тёмного текста используется светлая поддержка.
4. Размытие допускается только на сложной текстуре с сохраняющейся проблемой контраста после поддержки текста. Типичный радиус — 1,5–6 пикселей при короткой стороне 1080; 8 пикселей — крайний случай для длинного текста. Радиус масштабируется с разрешением.
5. Vision обнаруживает лица и визуально заметные объекты. Их области исключаются из маски размытия. При значительном пересечении с текстом, сильном движении или ошибке детектора blur выключается.
6. Маски строятся вокруг строк, с мягким пером. Интенсивность сглаживается во времени, а появление и исчезновение связаны с анимацией титра. Перемотка сбрасывает историю; обработка не продолжается за границами титра.
7. Контраст обработанной области проверяется повторно. Если его всё ещё недостаточно, усиливается контур букв. Размытие всего кадра не используется как запасной вариант.

Шаблонные плашки и декоративные элементы входят в анализ: если они уже обеспечивают читаемость, дополнительная обработка не нужна. Пользовательский стиль, расположение титра и существующие декоративные подложки сохраняются. Заливка букв рисуется поверх защитного контура, чтобы тонкий шрифт не выглядел полым.

## Предпросмотр и экспорт

Экспорт с титрами направляется через `VeloVideoCompositor`. Он получает уже собранный видеокадр и использует `AdaptiveTitleBackgroundRenderer` совместно с `TitleOverlayRenderer`.

Интерактивный просмотр сохраняет существующий нативный путь AVPlayer для тяжёлых камерных файлов. `TitlePreviewFrameSource` получает декодированный кадр через `AVPlayerItemVideoOutput`; тот же рендерер формирует прозрачный слой букв и локальной поддержки. Необработанные участки остаются прозрачными и показывают исходное видео. Анализ выполняется вне главного потока, одновременно обрабатывается не более одного кадра; устаревшие запросы объединяются до последнего.

Если декодированный кадр пока недоступен, используется актуальный постер, а при его отсутствии — обычный титр без анализа фона. Миниатюры библиотеки без реального видео также показывают исходный дизайн шаблона.

## Границы реализации

Это локальная модель читаемости с детекцией лиц и заметных областей, а не оценка художественной ценности сцены универсальной AI-моделью. Автоматического перемещения уже размещённых титров нет: положение сохраняется, чтобы композиция и строки не прыгали во время чтения. Локальная защита не заменяет ручную оценку режиссёром, особенно для очень прозрачного, мелкого или намеренно малоконтрастного текста.

Предпросмотр может пропускать промежуточные кадры анализа под нагрузкой; общий алгоритм и геометрия совпадают с экспортом, но временная история при разных частотах кадров может немного отличаться. Существующая функция стабильного просмотра по-прежнему может опускать отдельные видеоэффекты. Проверка HDR на реальном HDR-дисплее в эту валидацию не входит.

## Проверки

`AdaptiveTitleBackgroundTests.swift` проверяет сохранность читаемого кадра, светлый/тёмный текст, порядок усиления, защиту объектов и экшена, мягкость масок, локальность, существующие плашки, выделенные слова, повторный кадр, перемотку, временные границы, а также совпадение прозрачного предпросмотра с композитным изображением в горизонтальном, вертикальном и квадратном форматах.

Интеграционный тест строит видеокомпозицию и получает кадр через `AVAssetImageGenerator`, проверяя реальную видимость белого титра на белом видеоисточнике. Сравнение для визуальной проверки содержит три колонки: исходник, прежний титр, адаптивный титр.

```sh
./Scripts/dev-test.sh --jobs 2 --no-parallel --filter 'adaptiveTitle|[Tt]itle|[Ss]afeFit'
./Scripts/build-app.sh
```

Для сохранения PNG задайте `VELOEDIT_ADAPTIVE_TITLE_QA_DIR` при запуске тестов.

Результат проверки 8 сентября 2026: 64 связанных теста прошли, включая отдельную проверку отсутствия двойной заливки при появлении полупрозрачного титра.
