# «тест 7»: пропущенные исходники и общие правила ИИ-монтажа

## Результат аудита

Проверен сохранённый проект и самый ранний checkpoint готового AI Edit, до последующих ручных изменений. Оригинал прочитан напрямую через JSON, без открытия в ProjectStore и без записи в пакет.

- Исходники: **13 видео, 57:10,69** материала.
- Первоначальный фильм: **40 фрагментов, ровно 5:00, представлены 11 из 13 видео**.
- Текущий фильм: **38 фрагментов, 4:43,30**. Пользователь подтвердил последующее удаление; сокращение не отнесено к ошибкам генерации.
- В обоих вариантах **нет обратных перестановок** по сохранённым датам съёмки и sourceStart внутри файлов. Карта исходников также следует этой последовательности.

| Полностью пропущенное видео | Длительность исходника | Доступных кандидатов | Что установлено |
| --- | ---: | ---: | --- |
| GX010505.MP4 | 2:00,45 | 32 | В плане отклонён один кандидат около 118,108 с с причиной unsafeCrop. Альтернативные пригодные диапазоны существуют; отказ от одного кадра не объясняет исключение всего файла. |
| GX010569.MP4 | 1:13,97 | 23 | Пригодные неповторяющиеся моменты не получили места в итоговом отборе. |

Журнал записал для обоих файлов `noNarrativeFit`. Это была общая резервная причина, а не доказанный вывод о содержании. Код также мог объявлять весь исходник небезопасным по одному проблемному кандидату. В обоих анализах есть предупреждение, что Qwen3-VL не оценила шесть сцен и использовалась локальная оценка. Это ограничивает уверенность семантического анализа, но не доказывает непригодность видео.

Отбор был сильно неравномерным: GX010519 получил **87 с**, GX010564 — **1,97 с**, два файла — ноль. Разная продолжительность допустима, однако длительные планы из уже представленных исходников не должны автоматически вытеснять все пригодные моменты других записей.

## Общие изменения

Это изменение алгоритмов и проверок ИИ-монтажа. Веса языковой/визуальной модели не переобучались; индивидуальные названия файлов и UUID не используются в правилах.

1. Финальная автоматическая сборка проверяет каждый пропущенный исходник и резервирует пригодный неповторяющийся момент, если позволяют длительность и лимит кадров. Дополнительный кадр может заменить необязательный повторный план из уже представленного файла.
2. После отклонения кадра по безопасности рассматриваются другие диапазоны того же исходника. Отклонённый кандидат повторно не вставляется.
3. Явные исключения файлов и содержания сохраняются. Неподтверждённые, непригодные и настоящие дубли не вставляются ради количества файлов.
4. Проверка повторов использует фактически обрезанные диапазоны: пересечение исходных кандидатов не равно повтору на таймлайне.
5. Улучшение начала и конца фильма сохраняет уже достигнутое представительство исходников.
6. Сохраняются решения по исходникам: включение, пользовательское исключение, недоступность, отсутствие анализа, качество, небезопасные диапазоны, подтверждённый дубль, лимит кадров, длительность или необъяснённый пропуск. Для дубля указываются выбранные кандидаты, которыми подтверждается повтор; для пропуска — доступные альтернативы.
7. Итоговая проверка выявляет необъяснённые пропуски и нарушения порядка. Пока черновые варианты ещё выбирают кадры, пропуски служат замечанием; после финальной сборки становятся ошибкой редакционного качества. Возможность сохранить воспроизводимый фильм с предупреждениями остаётся.

Правила применяются к обычной автоматической видеопоследовательности. Существующие ограничения этапа финальной сборки для ручных, связанных и ускоренных/замедленных композиций сохранены.

## Проверка на данных проекта

Автоматическая пересборка выполнена **в памяти**, результат записан только в `Build/SourceCoverageQA/reassembly.json`. Получилось **42 фрагмента, 13 из 13 исходников, ровно 300 с**, без обратного порядка, повторов диапазонов и превышения подтверждённой длительности планов в структурной проверке.

В проверочном результате найдены альтернативы:

- GX010505: примерно 4,367–7,233 с исходника;
- GX010569: примерно 50,467–53,033 с исходника.

Через AVFoundation декодированы и визуально просмотрены начало, середина и конец обоих диапазонов. На первом виден велосипедист спереди, на втором — движение по лесной дорожке за велосипедистом; в конце второго камера поворачивается, и человек уходит к краю. Это подтверждение доступности материала, а не художественная приёмка нового фильма. Полная генерация с повторным подбором музыки, контролем всех кадров и экспортом нового фильма в этом аудите не выполнялась.

Исходный манифест: SHA-256 `534a5171a80b278ae797d5ad2c99118f62bffc16b16478568d9ee1743f7a3b85`. Проверка сравнивает его байты до и после чтения/пересборки.

## Регрессии и ограничения проверки

- Новые тесты: представительство источников при уже набранной длительности; альтернативный кадр после отказа; настоящие дубли; исключённые файлы и теги; лимит кадров; порядок внутри/между файлами; пересекающиеся кандидаты с непересекающимися монтажными диапазонами; сохранение доказательств; аудит реального проекта без записи в него.
- Расширенный прогон содержит 157 тестов. Функциональные проверки прошли; один тест скорости анализа 300+ файлов превысил порог 12 с при одновременных сборках (13,03 с). При предыдущем прогоне он прошёл за 10,38 с. Отдельное повторное измерение прошло за **6,10 с**, см. `performance.log`.
- Отдельный ранее существовавший тест `sourceTimelineRestoresTest3OrderAndKeepsBuggyFilesTogether` воспроизводимо получает две сцены вместо трёх ещё на этапе StoryEngine. Его прежнее воспроизведение описано в `Docs/Validation/MagicBrush/REPORT.md` и `previous-classifier-comparison.log`. Ожидания не изменены; этот тест исключён из указанного прогона, но его сбой не объявлен исправленным.
- Итоговый прогон **22 тестов** прошёл: новый механизм, автоматическая сборка и ограничения длительности, включая чтение реальных кадров и структурную проверку пересборки (`final-source-audit.log`).
- Полная сборка приложения и CLI, проверка подписи и итоговая идентичность исходников фиксируются в `final-build-app.log` и `build-identity.json`. Предыдущая попытка остановилась из-за изменения исходника во время компиляции; итоговая сборка **2026.258.085207** успешно завершена на зафиксированном дереве. Подпись проверена, хеш приложения совпадает с текущими исходниками; исходный «тест 7» остался побайтно неизменным.

## Воспроизведение

```sh
VELOEDIT_SOURCE_COVERAGE_PROJECT='/path/to/project.veloedit/project.json' \
VELOEDIT_SOURCE_COVERAGE_OUTPUT="$PWD/Build/SourceCoverageQA" \
./Scripts/dev-test.sh --filter 'SourceCoverageTests|sourceCoverageRealProjectReadOnlyAudit'
```

Опциональный аудит ожидает проект, содержащий ранний checkpoint готового фильма с необъяснённо пропущенным материалом. Без переменных окружения этот тест не обращается к пользовательским проектам. Для чтения видео требуется доступный системный декодер macOS.
