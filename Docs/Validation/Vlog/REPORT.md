# «Влог»: реализация и проверка, 2026-10-04

Рабочая первая версия локального речевого монтажа. Полная приёмка качества по ТЗ ещё не закрыта: нет размеченного корпуса 60 минут / 6 говорящих, отложенной части и 500 размеченных границ слов. Нельзя заявлять WER ≤ 8/18%, покрытие разборчивой речи ≥ 98%, p95 ≤ 200 мс или превосходство выбранной модели.

## Реализовано

- `FilmPreset.vlog`, существующий первый вопрос с четырьмя ответами, сохранение прежнего стандартного пресета; настроение и явные настройки независимы. Совместимые optional-поля в проектах.
- Нативный отдельный `VeloEditSpeechWorker`: AVFoundation 16 кГц mono, Silero VAD через ONNX Runtime, WhisperKit/Core ML. Первый звуковой track; выбор другого track/канала пока не представлен в UI.
- Вся доступная речь каждого исходника во всех режимах AI, включая Fast, до визуального shortlist. Речевые кандидаты сохраняются в анализах.
- Порции 24 с с контекстом по 2 с. Проблемная порция без подтверждённого текста повторяется с контекстами по 12 с; остальные повторно не распознаются. VAD, границы, logprob и повторы проверяются независимо. Сохраняются необработанные оценки и причины пропусков.
- Изолированный процесс, последовательная очередь ASR, остановка фонового анализа перед влогом, пауза при перегреве. Атомарные checkpoints с SHA-256; подтверждённые порции переживают отмену. Весь PCM длинной записи не загружается в память.
- Кэш включает SHA-256 исходника, дорожку, mono-downmix, язык, версию алгоритма, идентичность runtime/моделей/VAD/подготовки и alignment. Итоговый JSON также проверяется по SHA-256.
- Пакет 632 068 998 байт: фиксированные файлы, revisions и SHA, токенизатор, VAD и notices. Загрузка с возобновлением, локальный импорт, атомарная установка и замена повреждённого пакета, проверка места. В собранном приложении пакет вложен в Resources; Python пользователю не нужен.
- Хронология по существующему SourceTimelineAnalyzer; неопределённость часов камер сохраняется в отчёте. Голос 1×; сокращаются только длинные акустически подтверждённые паузы между завершёнными фразами. Недостижимая точная длительность сообщается, слова ради неё не обрезаются.
- Обычные редактируемые `TitleTimelineItem`; фразовые субтитры без фиктивных равномерных таймкодов и подсветки слов. Сохранение ручного текста, стиля, отключения, удаления и границ при повторной генерации.
- Привязки по исходной речи, карта кусочной скорости и фактический playback clock с перекрытиями переходов. Trim/split/ripple; reverse и freeze не публикуют неподтверждённые речевые подписи. SRT и WebVTT.
- Независимые команды субтитров и названий частей; отключение голоса убирает автоматические субтитры, явное «оставь субтитры без звука» разрешает их.
- Музыка только из доступной локальной библиотеки в речевом сценарии, голос сохраняется при отсутствии музыки; ducking привязан к речи. Нейросетевое шумоподавление не включено без слепого A/B.
- CAS по ревизии проекта, checkpoints/undo, состояния частичного результата. Проверка покрытия относится только к распознанным фразам и явно не называется WER или полнотой всей разборчивой речи.
- Исправлено преобразование AVFoundation → Core Image для повёрнутых видео: при прожиге титров исходник IMG_3747 ранее переворачивался.

## Выбор движка

Первичный runtime: vendored Argmax OSS (`f4e5d6be37ec820614fb0d72037e76c22d4c16f7`), WhisperKit, ONNX Runtime 1.24.2. В локальном tokenizer loader удалён сетевой fallback. Использованы исходники upstream, а не имитация API.

Модель: `argmaxinc/whisperkit-coreml/openai_whisper-large-v3-v20240930_626MB`, revision `0f63a7800b00dd0226abd051b906c246e1907482`; tokenizer `openai/whisper-large-v3-turbo` revision `41f01f3fe87f28c78e2fbf8b568835947dd65ed9`. Полный список hashes — `Resources/Speech/package.json`.

Silero: `1e261b036686cd0017d500ee96acd1c4ba572a9d`, официальный ONNX.

GigaAM: исследовательский стенд Python, официальный `v3_e2e_rnnt`, исходники `7447938d791c4f3e643386ee22c33777004293a5`; checkpoint SHA-256 `f60c62fe45902d967000770a12f260de7c5ac4d4b8e5e852f1df8c548e3958b5`. CPU, 4 потока, Torch 2.14.1. Загрузка модели 18.05 с, два фрагмента по 20 с заняли 0.443 и 0.436 с. Это узкое измерение после загрузки, не общий показатель производительности. В таймкодах второго фрагмента слово «нары.» занимает 54.0–60.84 с; такой результат нельзя автоматически включать как точное выравнивание. Артефакт: `Build/GigaAMComparison/result.json`; запуск: `Scripts/benchmark-gigaam.py`.

Контрольная полная large-v3: оригинальный Core ML FP16 пакет 3 095 670 659 байт, тот же Argmax model revision. На тех же 20 с (32–52 с исходника): прогрев 21.71 с, ASR вместе с alignment 6.53 с, пиковый RSS worker 1.89 GB. Результат получен с `sandbox-exec (deny network*)`; текст также содержит «сотовых километров». Артефакты `Build/FullV3Comparison/package.json`, `transcript.json` содержат hashes, исходные оценки и слова. Точность не оценивалась по отсутствующему эталону.

Turbo оставлен основным для прототипа: рабочий нативный offline путь и меньший пакет. Качество не объявляется лучшим. GigaAM ONNX/CTC, WhisperX и альтернативный runtime whisper.cpp остаются кандидатами, а не фиктивно подключёнными движками. Все модели не запускаются на каждом пользовательском файле.

Источники API: [Argmax OSS](https://github.com/argmaxinc/argmax-oss-swift), [GigaAM](https://github.com/salute-developers/GigaAM), [Silero](https://github.com/snakers4/silero-vad), [правило Whisper no-speech](https://github.com/openai/whisper/blob/main/whisper/transcribe.py).

## Проверки и ограничения

Mac: Apple M4, 32 GiB. Пять пользовательских файлов, суммарно 476.23 с; ручных эталонов в папке нет. Исходные тексты и логи остаются локально в `Build/SpeechValidation`. Статус `ready` означает завершение технических проверок, а не отсутствие ошибок ASR.

Автоматические проверки охватывают обратную совместимость настроек, mute-исключение, паузы, целые слова, split/trim, reverse, карту скорости, переходы, SRT/VTT, ручные правки/удаления/тайминги, повреждение пакета, создание влога без visual candidates и проверку невозможной точной длительности. Проверена запись/повторное открытие проекта с режимом и предпочтениями. Имеющиеся тесты actual preview/MP4 parity также пройдены.

15 минут синтетического контроля без речи (5 минут цифровой тишины, 5 минут brown noise, 5 минут гармонических тонов): **0 опубликованных слов / 0 фраз**, 162.52 с, сеть запрещена. VAD дал один подозрительный интервал; он помечен как неполный без выдуманного текста. Это не заменяет контроль на разнообразной реальной музыке и шуме.

Часовой файл — повтор пользовательской записи для проверки памяти, checkpoints, отмены и продолжения; не независимый корпус качества. Итоги сохраняются в `Build/SpeechValidation/offline/results.json`. Измеряется RSS самого worker; память внешних Core ML/ANE служб не включена. Раздельное время alignment пока не отделено от ASR.

Не закрыты: 60 минут / 6 говорящих с эталонами, отложенные 20 минут, 500 границ слов, ручной аудит отрицаний/имён/чисел, WER и p95, 20 слепых A/B для очистки, M1/16 GB, запуск на отдельном чистом Mac. Смысловые перебивки, выбор дублей и сложные диалоги относятся к следующему этапу ТЗ.


## Финальные измерения устойчивости

Часовая повторяющаяся запись завершена при запрещённой сети: 150 порций, 3856 слов, 575 фраз; результат частичный (113 предупреждений о неподтверждённой речи/границах). Общее время с преднамеренной отменой и новым запуском — 722.97 с. Второй запуск использовал 3 завершённые порции; после запуска ASR+alignment занял 572.50 с, VAD 15.24 с. Пиковый RSS самого worker — 198 623 232 байт; это не суммарная память Core ML/ANE. Отмена процесса — 0.008 с после запроса. Контрольные JSON — рядом с этим отчётом.

`./Scripts/build-app.sh` успешно собрал `Build/VeloEdit.app` (около 1.3 GiB). Проверены `codesign --verify --deep --strict` и SHA-256 всех 26 вложенных файлов speech package. Worker связан с системными framework/dylib; пользовательские Python/Homebrew для речи не нужны. Подпись локальная ad-hoc, проверка на другом чистом Mac остаётся открытой.

В последнем профильном наборе: 12 XCTest, 27 дополнительных Core tests, 1 проверка сохранения режима в AppModel — без ошибок. Отдельный тест actual preview/MP4 с речевым титром после двух переходов прошёл. Журналы в `logs/`. UI automation не дала прочитать окно приложения: две попытки завершились timeoutReached; визуальная проверка всего опроса в живом приложении не объявляется пройденной.


Сквозной offline-прогон штатного `VeloEditPipeline` из CLI в отдельном тестовом bundle с вложенным worker/пакетом: `IMG_3094.mov`, 42.38 с, режим Fast, без предварительных visual candidates. Создан 1 клип и 17 субтитров. Без музыки: 73.36 с с первым прогревом; повторный локальный автоподбор: 0.53 с; конкретный локальный трек: 0.62 с. Последние два запуска использовали речевой кэш. На этом шаге проверялась сборка композиции, а не полный новый MP4; соответствующее предупреждение в delivery report сохранено. Сводка — `offline-pipeline-results.json`. Результат выявил отдельную ошибку распознавания строки «Стиль: Влог» журналом intent; для неё добавлена структурная проверка наличия речевых результатов всех исходников и скорости голоса.


Пятый файл (`Интервью.MOV`) повторно завершён без сети: 199 слов, технический статус ready, VAD 0.50 с, ASR+alignment 13.05 с после прогрева 67.72 с. Первый запуск этого файла был прерван во время параллельной пересборки debug executable; финальный повтор использовал изолированную копию worker. Сводка всех пяти файлов — `user-corpus-results.json`. На IMG_3747 и VID_20260529 остаются неподтверждённые участки, исходный голос сохранён.

Если обрезка затронула вручную переписанную фразу, для которой нет достоверного соответствия каждого исправленного слова аудио, её текст остаётся в инспекторе, но подпись отключается с пояснением до проверки пользователем. Так удалённая речь не появляется в SRT или MP4 под видом подтверждённого текста.


## Оформление и выбор пользователя

На одном исходном фрагменте IMG_3747.MOV 00:32.000–01:12.000 отрисованы четыре варианта: Киношный, Влог, Путешествие, Соцсети. Файлы — `output/VlogStyles/`, общий SRT и сравнение 2×2 — там же. Текст получен автоматически и не исправлялся вручную; тайминги одинаковые. Каждый отдельный MP4: 720×1280, 30 fps, 40.000 с, H.264/AAC. Декодированный звук во всех четырёх и общем сравнении имеет одинаковый MD5. Подсветка использует измеренные слова, но точность исходного alignment на ручной разметке ещё не принята.

Пользователь отверг киношные субтитры и попросил выбирать оформление в начале настройки каждого фильма. В опросе сначала выбирается стиль монтажа; для Влога/включённых субтитров следующим вопросом идут **Влог / Путешествие / Соцсети**. Киношного оформления в этом вопросе и параметрах фильма нет. Выбор хранится в optional-поле `DirectorBrief.subtitleStyle` конкретного проекта и применяется к автоматически создаваемым субтитрам. Старым проектам стиль не навязывается; индивидуальные ручные правки защищены. В параметрах фильма доступны те же три варианта. Киношный образец оставлен среди результатов сравнения и в общем ручном каталоге титров.

Исправлены повторяющиеся слова при подсветке, пересчёт измеренных таймингов при trim/speed ramp, сохранение выбранной подсветки при off/on и генерации. Если ручной текст больше не соответствует измеренным словам, подсветка не выдумывает новое соответствие. Смена только оформления не считается ручной коррекцией времени из-за погрешности floating point.

Финальный профильный набор после этих изменений: **15 XCTest + 5 Core tests + 1 AppModel test**, без ошибок. Проверены реальный preview/MP4 после переходов, повторяющиеся слова, переменная скорость, обрезка, совместимость команд обычных титров, сохранение выбора и отсутствие переноса оформления в другой проект. Сквозной offline-прогон на IMG_3094.mov прошёл для всех трёх оформлений: по 17 подписей; Соцсети содержит 58 измеренных слов для подсветки. Это проверка сборки композиции; новый MP4 в этом конкретном прогоне не экспортировался. Видеопримеры проверены отдельно. UI опроса в живом приложении ещё не проверен автоматизацией.

После последней правки выбора оформления полный `./Scripts/build-app.sh` успешно выполнен; подпись bundle и SHA-256 всех 26 файлов пакета проверены повторно. Обновлённое сравнение трёх вариантов без киношного — `output/VlogStyles/comparison-3-styles.mp4`.
