Лог: [build-app-final.log](build-app-final.log), идентификатор: [final-build-identity.json](final-build-identity.json). После неё исходники приложения не менялись в рамках этой задачи.

Чтобы не закрывать уже работавшую старую копию VeloEdit, интерфейс проверялся на APFS-копии этого bundle с отдельным CFBundleIdentifier и новой ad-hoc подписью. Исполняемый файл и ресурсы совпадают с итоговой сборкой. Проверены запуск, открытие существующего проекта, кнопка «Обновить названия частей», сохранение ручной правки, повторное обновление, повторное открытие и экспорт из приложения.

Первая попытка открытия через список файлов выбрала родительский каталог; повторное открытие по точному пути успешно. Это не засчитано как ошибка чтения проекта.

Старые названия сохранены там, где уже был заголовок части; для двух частей без него добавлен резерв. Старые автоматические надписи внутри частей удалены как дубли.

## Воспроизведение

Команды сборки, тестов и обновления названий приведены в [README.md](README.md). Для реального замера на подготовленной одноразовой копии:

```sh
python3 Scripts/smart-chapter-title-study.py Build/SmartChapterTitles/development.veloedit
Build/veloedit-cli render Build/SmartChapterTitles/ui-portrait.veloedit Build/SmartChapterTitles/ui-portrait.mp4

VELOEDIT_RELIABILITY_TITLE_INPUT="$PWD/Docs/Validation/SmartChapterTitles/export-portrait-input.json" \
VELOEDIT_RELIABILITY_TITLE_OUTPUT="$PWD/Build/SmartChapterTitles/export-portrait-frames" \
CLANG_MODULE_CACHE_PATH="$PWD/Build/SmartChapterTitles/ModuleCache" \
swift test --skip-build --disable-sandbox --scratch-path Build/SmartChapterTitles/Swift \
  --filter inspectSavedExportTitleVisibility
```

`--skip-build` допустим только после сборки тестов из README. Аналогичная команда с `wide` проверяет горизонтальный MP4. Скрипт замеров принимает только одноразовые копии внутри `Build/SmartChapterTitles/`; исходные пользовательские проекты не перезаписывались.

## Непроверенные критерии и ограничения

- Доступны восемь реальных частей из двух контрольных монтажей; их независимость по поездкам не установлена. Только одна часть проверялась живой моделью в повторном реальном замере. Нет 50–100 частей минимум по десяти темам с просмотром и разметкой человеком.
- Порог 90%, нулевое число конкретных домыслов на независимом наборе и ошибки/резервы по темам не подтверждены. Синтетические случаи на 11 темах проверяют маршрутизацию и основания, а не смысловую точность.
- Реальные времена получены только для balanced. Все четыре режима имеют явные бюджеты, но сравнительная оценка качества и скорости по режимам не выполнена. Влияние на полное время создания нового фильма отдельно не измерено.
- Новое декодирование при скудных свидетельствах не реализовано. На старых анализах это повышает долю резервов; нужна проверка на материале с достаточным покрытием до вывода о качестве модели.
- Защита при сохранении, отмене, повторной генерации и устаревшем ответе покрыта автоматическими тестами. Полный сценарий аварийного завершения приложения на каждом этапе новой сборки фильма отдельно не разыгрывался.

Эти ограничения не скрыты за результатами регрессии: выполнена реализация и проверка её сохранности, но широкая смысловая приёмка остаётся открытой.
