## Что изменено

| Пункт отчёта | Исправление |
|---|---|
| 1. Обрывы первого запроса и повтор тяжёлой работы | Потоковый клиент VLM, отдельный бюджет ожидания первого токена с учётом числа изображений, ограничение общего времени запроса. Тайм-аут больше не запускает тот же тяжёлый inference ещё два раза. В трассе есть domain/code/описание ошибки, время первого токена и финальные метрики. Кэш принимает только полностью полученный и проверенный ответ. |
| 2. Запрошенная глубина выдавалась за завершённую | В проект сохраняется `AIExecutionEvidence`: состояние анализа кадров/звука, план и факт нейрооценок, план и факт независимых перепроверок, наличие и реальная битность модели. Незавершённые результаты не удовлетворяют профилю и повторяются при следующем анализе. Убрано безусловное повышение глубины в production pipeline. Старые результаты без свидетельств перепроверяются один раз. Интерфейс и сообщения прогресса различают полный и частичный результат. |
| 3. Неуспешные попытки считались valid-vlm | Benchmark считает успешно применённые оценки и отдельно показывает `vlm-failed`, `partial-vlm`, `model-unavailable`, `unverified-legacy`. Число запросов остаётся числом попыток. |
| 4. Неработающий MLX | Непоставляемый backend исключён из доступных вариантов. Старые MLX-настройки читаются и переводятся на соответствующий Ollama-профиль. Приложение показывает фактический runtime. Нативный MLX backend не добавлялся. |
| 5. Сравнение роликов ошибочно обозначено особенностью Maximum | Обозначено общей возможностью всех режимов; сам проход сохранён. Maximum выполняет до двух отдельных запросов перепроверки без кэша, учитывает их успех и больше не теряет ошибку через `try?`. Если кандидаты есть, произвольный порог больше не может убрать все перепроверки. |
| 6. Фиктивная битность | Битность показывается из `details.quantization_level` установленной Ollama-модели. Смена одного поля настроек не выдаётся за переквантование весов. Legacy Q8/FP16 декодируются, но модель определяется её tag; Maximum на Mac с меньшей памятью больше не обещает Q8 для стандартного Q4 tag. Для иной битности нужен соответствующий установленный tag. |
| 7. Эвристические компоненты выдавались за отдельные сети | Диагностика явно называет локальные дескрипторы и DSP правилами без отдельной нейросети. Их работа сохранена. Qwen, Apple Vision и опциональное распознавание речи учитываются отдельно. CLIP и дополнительная аудионейросеть не добавлялись. |
| 8. Balance полностью пропускал пейзажи | После приоритетного отбора бюджет заполняется репрезентативными кандидатами, включая спокойные сцены. Анализ непустого набора кандидатов больше не пропускает VLM из-за порога interest. Fast сохраняет бюджет до двух кандидатов. |

Скрытый лимит 4/6 изображений для Quality/Maximum снят: используются до 8/12 изображений на кандидата. Вместо уменьшения контекста размер пакета уменьшен до 2/1 сцен. Общие лимиты кандидатов остались 2/6/12/18. Режимы не изменяют размер или качество финального экспорта.

Чат продолжает использовать отдельную Qwen3 4B; точные команды сохраняют быстрый путь без модели. Назначение переключателя уточнено в интерфейсе: глубина анализа видео. Приложение удерживает систему от автоматического сна только во время анализа и снимает удержание при выходе или отмене.

ASR остаётся опциональным и локальным. Интерактивное приложение может запросить разрешение Speech. CLI/тесты не открывают невидимый системный запрос разрешений; при отсутствии ранее выданного разрешения они сохраняют явную диагностику недоступности ASR. Настройки TCC не изменялись.

## Реальные проверки и сборка

На этом Mac установлены все четыре видеомодели: Qwen3-VL 2B (1,89 ГБ), 4B (3,30 ГБ), 8B (6,14 ГБ), 30B-A3B (19,60 ГБ). Реальная битность каждой — Q4_K_M; она получена из Ollama, а не из настройки приложения. Полные digest и сведения об установке находятся в `installed-models.json` и `model-install.log`. 8B и 30B установлены в этом этапе.

Все замеры выполняются последовательно, без параллельной сборки или тестов, с временным предотвращением сна. Исходные видео и пользовательский проект не изменяются. Холодный проход означает новый кэш приложения; системный и внутренний кэши Ollama не сбрасывались. Повторный проход удаляет только analyses и очередь в отдельной копии проекта, сохраняя валидный кэш. Это одиночные функциональные прогоны, не медиана/p95 и не гарантия скорости для произвольного фильма. Во время ранних прогонов в фоне загружалась модель 30B; тепловые состояния сохранены в `live-summary.json`.

В каждом холодном проходе выше получен и применён реальный ответ нужной модели; неуспешных VLM-запросов нет. Повторные проходы Fast/Balance/Quality берут проверенные ответы из кэша без нового inference. Maximum в повторном проходе берёт основную оценку из кэша, но **снова выполняет отдельный inference перепроверки**: это подтверждено `vlm.runtime` и `vlm.recheck-completed`. В коротком исходнике один кандидат, поэтому фактический план — одна перепроверка; лимит режима — две. Это повторная оценка той же моделью, не другой моделью или агентом. Сырые JSON и трассы — `Build/AIModeFixes/short/` и `Build/AIModeFixes/maximum/`.

Первый живой тест чата подтвердил отдельный Qwen3 4B и быстрый точный парсер (`director-live.json`): 0,019 с для подготовки точной команды громкости, 11,77 с для ответа модели. 9 тестов состояния приложения/чата прошли (`app-tests.log`). В ответе модели нашлась дополнительная недоработка: вместо запрошенного названия она только подтвердила отсутствие изменений. Поэтому режим совета получил отдельный промпт без противоречащих инструкций подготовки правок. В режиме совета код также безусловно исключает команды, normalizedBrief и замену фрагмента, даже если модель их вернула. Регрессия подаёт такой некорректный план и проверяет его обезвреживание; живой тест усилен проверкой наличия конкретного предложенного названия.

После исправления реальная Qwen3 4B ответила **«Путь под деревьями»**, за 5,38 с, с нулём команд. Точная команда «громкость музыки 20%» распознана за 0,007 с и вернула `setMusicVolume(0.2)` через парсер. `director-live-final.json`. Эти замеры относятся к получению совета/подготовке плана; команды в интеграционном тесте не применяются к пользовательскому проекту. Сравнение двух одиночных ответов не является общей гарантией ускорения чата.

Для воспроизведения видеопроверки нужен новый `--label`, поскольку существующие копии намеренно не перезаписываются:

```sh
python3 Scripts/performance-study.py --cli Build/veloedit-cli \
  --project Build/AIModeFixes/eight-second-source.veloedit \
  --label verify-new --root Build/AIModeFixes --modes fast balanced quality maximum
python3 Docs/Validation/AIModeFixes/validate-runs.py verify-new
```

Без аргументов `validate-runs.py` проверяет сохранённые контрольные прогоны short/maximum/calm/first-original. `runtime-source-equivalence.json` проверкой полного хэша подтверждает, что после контрольных видеопрогонов менялся только `LocalDirectorAgent.swift`, а видеоконвейер и ресурсы остались идентичными. Кроме того, SHA-256 окончательного CLI полностью совпадает с бинарным файлом, на котором выполнены Maximum и шесть проверок кэша/отказов: CLI идентичен байт-в-байт.

Ограничения проверки: доступ к нативному окну заблокирован экраном блокировки macOS; визуальная проверка интерфейса не проводилась. Live ASR недоступен в CLI без ранее выданного Speech-разрешения, и приложение теперь явно это показывает. Проверка интеграции с распознанной речью использует внедрённый тестовый transcript; она не выдаётся за фактическое распознавание Apple Speech. Художественное качество монтажа этими проверками не доказывается.
