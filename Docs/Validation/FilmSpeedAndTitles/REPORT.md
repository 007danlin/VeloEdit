# Film Speed and Titles — результат реализации

18–19 сентября 2026. Это частичная сдача ТЗ: исправление титров подтверждено на сохранённом фильме; полная приёмка P0/P1 и цели сквозного ускорения пока не подтверждены.

## Что изменено

- OCR привязан к ID титра, версии алгоритма, сигнатуре монтажа, времени/реальному PTS, области текста и размеру декодированного изображения. Текст OCR, confidence и причина отказа сохраняются в свидетельстве.
- Для OCR декодируется реальный кадр до 1920 пикселей по длинной стороне. Проверка обычных кадров сохраняет прежние 640 пикселей и полный график точек; проверка титров добавлена отдельно. Порог 0,5 не снижен. Сопоставляются слова целиком с учётом повторений; совпадения с подстрокой недостаточно.
- Для каждого титра обязательны начало, середина и конец читаемой фазы с учётом фактической анимации. Сохраняются прежние пробы возле склеек. Композиция и новый контрольный MP4 проверяются независимо. Отсутствующее или устаревшее свидетельство не даёт положительного результата.
- Геометрически обрезанный/скрытый/неполностью размещённый текст отклоняется. Исправление оформления применяется только к указанным в замечании титрам; неизменившееся исправление не запускает ещё один проход. Сохраняются ограниченный бюджет и проверка, что ремонт не разрушил выдаваемый фильм.
- Доработан существующий RenderedProbeCache: версия формата, контрольная сумма, атомарная публикация, телеметрия, текущее состояние исходников и фактически используемых прокси. Телеметрические множества канонизируются, чтобы порядок Set не менял ключ между процессами.
- Чисто визуальный кэш может пережить изменение звука. Семантические, звуковые и экспортные свидетельства с ним не переносятся. При актуальном кэше кадров не строится ненужная композиция предпросмотра. Каждый новый MP4 проверяется отдельно; контрольный 1080p не используется как финальный 5K.
- Экспортные квитанции содержат SHA-256 и идентичность файла. Повторное использование требует целостности файла. Изменение содержимого при прежних размере и mtime также инвалидирует квитанцию.
- Для неизменного монтажа общая видимость точек и сигнатура вычисляются один раз на вызов проверки, затем к тем же точкам применяется отдельная область каждой категории. Повторная работа видимости обнаружена в профиле тяжёлого теста; сквозной выигрыш от этого изменения отдельно не измерен.
- Добавлены монотонные интервалы композиции, очереди/инспекции кадров, контрольного экспорта, независимого декодирования, OCR MP4, аудио, сериализации/сохранения. Записываются причины промаха кэша и PTS. Доставка промежуточного прогресса ограничена 10 Гц, смена этапа и конечные счётчики сохраняются.
- В интерфейсе отдельно показано состояние сохранения/проверки. После сохранения правка проверяется в фоне с контролем ревизии. Новая правка отменяет прежнюю проверку; запоздавший результат не заменяет актуальную версию.
- Новые команды не обходят ранее принятые команды в очереди. Если выбранный при отправке клип удалён, запрос явно отклоняется, а не переадресуется текущему выделению.
- Ранее «визуальная задержка» ручной правки записывалась равной времени изменения модели. Теперь отдельная метка появляется после публикации настоящего декодированного кадра paused preview. Это всё ещё не измерение физического вывода дисплея и не измерение слышимого звука.
- Добавлена команда `verify-film`: повторная проверка сохранённого плана без перегенерации истории, с сохранением результата через compare-and-swap.

## Воспроизведение дефекта титров

Сохранённый проблемный фильм: `Build/Performance/real-film/film.veloedit`. В старом кэше OCR на 1,75 с дал 0 для «В дороге»; итог — 6/7 требований. Независимый аудит старого MP4 показывает нестабильность OCR целого изображения при ширине 640: на 2,00 с текст не найден, хотя в версии кадра 1920 он найден. На остальных проверенных точках текст читается. Поэтому исправлено качество входного изображения OCR, а не понижен порог или выбран только удачный момент.

Новый контрольный MP4 на отдельной копии прошёл **7/7**. Все три заголовка — «В дороге», «На природе», «Багги» — распознаны в трёх обязательных точках каждый. Девять результатов MP4 имеют score 1,0. Сохранение и повторное открытие проверяются отдельными запусками процесса.

`unchanged-film.json` подтверждает равенство items, titleItems, переходов, музыки, исходной громкости, размера, fps и финального затемнения. Исправление проверки не меняло текст, оформление или монтаж данного фильма. Свидетельства: `title-evidence.json`, `reproduction.json`, `baseline-ocr.log`; кадры и полные квитанции находятся в тяжёлом каталоге исследования.

## Измерения и их границы

Сохранены исходники с незакоммиченными изменениями, git diff/status, исходный app/CLI и идентификатор новой исходной сборки в `Build/Performance/film-speed-and-titles/baseline-*`. Пользовательский проект и исходные медиа не редактировались.

Исходный обычный прогон: создание 493,591 с, финальный экспорт 125,735 с, проверка исходников 1,661 с. В создании повторно выполнялся анализ, поэтому это **не чистый baseline из готового анализа**. Трасса: 1109 физических декодирований, 1168 запросов кадров (1109 computed, 57 memory, 2 disk), 5179 уведомлений прогресса. По записанным параметрам одинаковых физических запросов источников не обнаружено. Старых интервалов недостаточно для полного критического пути; оснований для нового пакетного декодера не получено.

Отдельная функциональная перепроверка зафиксированного проблемного монтажа заняла 69,781 с с запуском CLI. Это не создание фильма и не сравнение до/после.

## Проверки

- Конечные целевые проверки прошли: 53 Core и все 19 App, всего 72 (`regressions-delivery.log`). Предыдущий набор из 43 проверок также прошёл (`regressions-final.log`). Включены положительные и отрицательные OCR-примеры 16:9/9:16, потеря декодирования, низкий контраст/прозрачность, выход за кадр, обрезка, устаревшее оформление, недостаточное покрытие, независимость MP4, повреждение кэша, замена исходника/прокси, замена артефакта с прежним mtime, отмена одного общего потребителя, сохранение/reopen, очередь команд и обновление настоящего paused preview.
- Первый полный запуск прервался с SIGBUS/stack guard в `tenIndependentEditContextsInfluenceFullDirectorVariantSelection`. Повтор на сохранённом исходном дереве прошёл, что выявило новую регрессию. Она исправлена: прозрачный reference-wrapper уменьшает стек generic-контейнеров JSONEncoder, сохраняя тот же Codable payload; сигнатура вычисляется один раз на проверку вместо повторного кодирования в каждом setter/filter. После исправления ранее падавший сценарий прошёл (0,987 с; `regression-signature-box.log`). Старые неуспешные прогоны сохранены для аудита.
- Повторный полный запуск после исправления стека остановлен через 688,607 с для проверки следующего изменения общей выборки видимых точек. Он **не считается прошедшим**. В момент остановки оставался `productionPipelineWithMoreThanThreeHundredAssetsRunsP6EndToEnd`; профиль показывал активный `StoryEngine.selectWithinEvent`. Все 19 App-тестов завершились успешно. Список ошибок и остановленного сценария сохранён в `full-tests-after-stack-fix.log` и `full-tests-after-stack-fix-status.json`. Целевой конечный прогон не заменяет этот полный запуск.
- Две ошибки тестов BPM и ошибка группировки test3 воспроизведены на исходном снимке этого этапа: 3 теста, 7 assertions (`baseline-regressions-current-snapshot.log`). Проверка стадии после отказа пустого фильма тоже падает на исходном снимке в обоих вариантах (`baseline-progress-failure.log`). Падавший новый сценарий на том же baseline прошёл. Временной тест на 300 источниках также не уложился в лимит при первом общем параллельном прогоне; его результат нельзя выдавать за измерение UI.
- Три дополнительных функциональных сбоя создания фильма — короткое фото, ожидаемая длительность автономного решения и отсутствие pairDistances — воспроизведены на сохранённом baseline: 3 теста, 6 assertions (`baseline-production-regressions.log`). Проверялось поведение; этот прогон пересекался со сборкой и не используется для сравнения скорости.
- Пять дополнительных сбоев при общем параллельном запуске повторены последовательно без фоновой сборки/экспорта и прошли: два музыкальных сценария каскада, выбор свежего трека, индекс 300 источников и обнаружение событий 300 источников (`isolated-timing-regressions.log`). Это не превращает незавершённый полный прогон в успешный.
- UI smoke предпоследней сборки (до канонизации телеметрии): приложение запущено, изолированный проект открыт, монтаж и новый статус сохранения отображаются. Затем Mac заблокировался; действие редактирования не выполнено. Тестовую копию нельзя считать прошедшей полную UI-приёмку.
- Полный bundle собран `./Scripts/build-app.sh`; подпись проверена `codesign --verify --deep`. SHA-256 конечных исходников и ресурсов совпадает с `BuildInfo.json`: `ba4b4afe8a7fb4f396d5aabbdeed99fbbc50c138af742e23c891bfd0ae7fae28`. Финальная CLI-версия прошла проверку фильма и экспорт. GUI-проверка конечной сборки остаётся заблокирована экраном блокировки; повторная попытка подтвердила блокировку.

## Что остаётся открытым

P0 не заявлен полностью принятым: нет пяти чередующихся пар до/после создания и повтора для «Быстро» и «Баланс», эквивалентного полного replay до/после с одинаковым планом проверки, полного успешного регрессионного прогона и слепого просмотра/прослушивания целых фильмов. Не реализован кэш произвольных отдельных видеокон/титров: сохранено консервативное общее инвалидирование визуального кэша при визуальной правке. Не изменены механизмы отмены последнего потребителя FrameCache; существующая изоляция отмены одного потребителя проверена.

P1 не заявлен полностью принятым: нет реальных 30 UI-замеров на операцию/нагрузку, p95 приёма команды и слышимого/видимого эффекта, полной матрицы составных запросов/ручных конфликтов под анализом и экспортом. Статус проверки и автоматизация реализованы; статистическая UI-приёмка требует продолжения после разблокировки Mac.

**Цели 20% / 40% / UI p95 ≤100 мс / локальная правка p95 ≤1 с не подтверждены.** Старшие режимы «Качество»/«Максимум» не измерялись; 8B/30B не скачивались, разрешения Speech/TCC не менялись. Ускорение всех режимов не заявляется. Сводка окружения не заменяет полный непрерывный контроль thermal/model digest/фоновой нагрузки.

## Воспроизведение

```sh
VELOEDIT_BUILD_CACHE_ROOT="$PWD/Build/Cache" VELOEDIT_BUILD_CLI=1 CARGO_NET_OFFLINE=true ./Scripts/build-app.sh
VELOEDIT_BUILD_CACHE_ROOT="$PWD/Build/Cache" ./Scripts/dev-test.sh --filter FilmSpeedAndTitlesTests
python3 Scripts/film-title-recheck-study.py --cli Build/veloedit-cli --project <отдельная-копия.veloedit> --output <новый-каталог> --count 5
python3 Scripts/film-title-trace-summary.py <каталог-трасс> --output <summary.json>
```

Скрипт перепроверки изменяет только указанную копию проекта и не выдаёт её времена за скорость создания фильма. Для обычных запусков используется прежний `Scripts/performance-film.py`. Полная сборка: `Build/VeloEdit.app`; итоговый журнал: `app-build-delivery.log`. Проверка соответствия конечного bundle исходникам — `build-identity-delivery.json`; предыдущая сборка серии — `build-identity.json`. Патч относительно сохранённого пользовательского дерева — `change.patch`.
