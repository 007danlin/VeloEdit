# Проверка открытия проектов и скорости монтажа — 12 сентября 2026

Проверка выполнена на macOS 26.6.2, arm64, в debug-сборке Swift Testing. Для реальных замеров использованы отдельные APFS-копии проектов из Downloads. Оригинальные проекты не служили тестовыми выходными файлами. Размеры приведены в десятичных МБ.

## Найденные причины

- В запущенной старой копии приложения обнаружено модальное предупреждение об отсутствии облегчённой видеокопии. Оно блокировало остальные кнопки. Предупреждения восстановления теперь идут в статус; ошибки, препятствующие работе, сохраняют обработку ошибок. Текущий выбор proxy уже умеет использовать оригинал без ложного предупреждения.
- Одновременно работали `Build/MusicSearch/VeloEdit.app` и `Build/VeloEdit.app`. Проверять результат нужно в заново запущенном основном bundle: уже запущенный процесс продолжает исполнять прежний код.
- Повторный `flushAutosave` заново записывал весь проект, хотя изменения уже сохранены. Убрано дублирующее сохранение; неизменённое состояние рабочего пространства пропускается без изменения ревизии и файла.
- Предпросмотр оптимистической правки ожидал actor хранилища, занятого сериализацией большого manifest. Теперь он получает неизменяемый снимок напрямую.
- В проекте на 105 фрагментов звук повторно обрабатывался после каждой правки. Кэш PCM учитывает исходный файл, его размер и дату изменения, диапазон и параметры обработки. Громкость и fades остаются в AVAudioMix, поэтому их изменение не пересоздаёт PCM. Повреждённые файлы восстанавливаются; публикация атомарная; очистка кэша сохраняет источники текущей композиции.
- Повторные нарезки одного видео заново загружали метаданные. Загрузка AVFoundation переиспользуется в пределах сборки композиции.
- Swift Testing выявил аварийный вызов UserNotifications вне `.app`. Вызов теперь выполняется только из bundle приложения.

## Измерения

| Копия проекта | МБ / фрагментов | Открытие файла | Предпросмотр с готовым кэшем | Сборка после trim | Готовый кадр после trim, включая сборку |
|---|---:|---:|---:|---:|---:|
| тест 4 | 37,9 / 10 | 925 мс | 33 мс | 23 мс | 61 мс |
| тест 5 | 54,7 / 50 | 1 333 мс | 84 мс | 75 мс | 106 мс |
| тест 6 | 133,7 / 105 | 3 239 мс | 220 мс | 212 мс | 246 мс |

До кэширования звука повторная сборка после trim в «тест 6» занимала 5 010 мс и нарушала установленный предел 3 секунды. После исправления — 212 мс. Первое заполнение отсутствующего кэша по-прежнему требует обработки звука и в проверке занимало около пяти секунд.

На каждом проекте декодированы кадры в начале, середине и перед концом фильма, затем кадр изменённой композиции. Пропущенных фрагментов, чёрных контрольных кадров и предупреждений в этих проверках нет. Разрешение композиции — preview1080p; проверяемые кадры уменьшены до 960×540. Это время подготовки изображения через AVAssetImageGenerator, а не измерение частоты кадров окна AVPlayer или задержки монитора.

## Регрессионные проверки

Заключительный полный прогон: **677 тестов в 20 наборах, результат passed, 108,36 секунды**. Подробный вывод, включая пропущенные специализированные сценарии, сохранён в `FullTests.log`.

Полный release-bundle пересобран командой `VELOEDIT_BUILD_SNAPSHOT=1 ./Scripts/build-app.sh`. В bundle включены ресурсы и Rust OVRLEY, проверка `codesign --verify --deep --strict Build/VeloEdit.app` успешна. Исходники после тестирования не изменились; SHA-256 исходников и готового bundle записаны в `SourceHashes.json` и `BundleHashes.json`. Журнал сборки — `AppBuild.log`.

- Быстрые повторные клики и переключение проектов: побеждает последний запрос, список недавних не дублируется.
- Повреждённый проект: текущий проект остаётся открыт, повторная попытка работает.
- Повторное сохранение: байты файла, дата и ревизия не меняются без правок.
- 30 быстрых trim: состояние изменяется синхронно, последний результат сохраняется после повторного открытия. Максимальное время изменения состояния в заключительном прогоне — 0,58 мс.
- Предпросмотр собирается при искусственно занятом хранилище; 100 склеек одной камеры декодируются корректно.
- Звук: переиспользование между экземплярами генератора, изменение диапазона/обработки/исходника, повреждение кэша и одновременные записи.
- Полный набор включает существующие проверки эффектов, переходов, титров, звука, восстановления, persistence/CAS и экспорта. Специальные сценарии, включаемые отдельными переменными окружения, перечислены как skipped в журнале.

Исходники для тестов скопированы в `/tmp/veloedit-performance-source`, чтобы изменения другим процессом не прерывали компиляцию. Для повторения на отдельной копии:

```sh
VELOEDIT_PERFORMANCE_COPIES=/tmp/veloedit-performance-copies ./Scripts/dev-test.sh --jobs 2 --no-parallel
```

`VELOEDIT_PERFORMANCE_COPIES` должна указывать только на каталог одноразовых копий проектов: открытие может мигрировать состояние восстановления, а playback создаёт кэш.

Ручная заключительная проверка кликов, прокрутки и воспроизведения в новом окне пока недоступна: инструмент управления компьютером сообщил, что Mac заблокирован. Автоматические проверки не заменяют эту часть проверки.
