# Проверка виджета нагрузки Mac — 12 сентября 2026

Проверено на Apple M4, 10 логических CPU, 32 ГиБ RAM. Проверочный исполняемый
файл собран непосредственно из тех же `SystemResourceMonitor`, `SystemGPUUsage`,
`SystemMemoryUsage` и `ProcessGPUUsage`, которые использует виджет.

## Исправления

- CPU: системные тики Mach, разница двух замеров, шкала всех ядер 0–100%.
- GPU: общая занятость устройства из `IOAccelerator/PerformanceStatistics`.
  Раньше раскрытый виджет показывал GPU только процесса VeloEdit.
  Для нескольких GPU показывается наиболее занятый, что объяснено в подсказке.
  Отсутствующий, нечисловой или недопустимый счётчик означает «Нет данных».
- RAM: анонимные страницы минус освобождаемые страницы, плюс wired и физический
  размер компрессора. Освобождаемый файловый кэш и распакованный размер сжатых
  страниц не прибавляются. Раньше показывалась память только VeloEdit.
- Цвет памяти соответствует системному давлению памяти, а не проценту занятой
  RAM. Нет доступа к этому показателю — нейтральный цвет и «нет данных».
- CPU и резидентная память самого VeloEdit подписаны отдельно.
- При недоступном показателе шкала не рисует маркер нулевой нагрузки.

Методика памяти соответствует разделению используемой памяти и файлового кэша
в [руководстве Apple](https://support.apple.com/guide/activity-monitor/view-memory-usage-actmntr1004/mac).
Структуры системных счётчиков определены в
[исходниках XNU](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/mach/vm_statistics.h).

## Проверка на настоящей нагрузке

В фоне работали другие приложения и сборки. Фоновая загрузка CPU поэтому
не равна нулю. Все временные тестовые процессы завершены.

| Проверка | Монитор виджета | Независимая сверка |
| --- | --- | --- |
| CPU до нагрузки, среднее | 33,00% | `top`: 34,20% |
| CPU, 10 тестовых процессов, среднее | 100,00% | `top`: 99,37% |
| CPU после остановки тестовых процессов | 59,35% | `top`: 55,37% |
| GPU до непрерывной нагрузки | 0% | `ioreg`: 0% |
| GPU, непрерывная очередь Metal | 100% | `ioreg`: 100%; разница 0 п.п. |
| GPU после остановки, последние три замера | 1% | Показания вернулись к фону |
| Используемая память, 34 замера | Примерно 25–26 ГиБ | `vm_stat`: средняя абсолютная разница 5,01 МиБ, максимальная 28,45 МиБ |

`top`, `vm_stat` и виджет измеряются последовательно или в разных секундных
окнах, поэтому на меняющейся нагрузке числа не обязаны совпадать до последнего
знака. Непрерывный GPU-тест выполнил 1600 командных буферов Metal. В первом
GPU-тесте между командами были паузы: соседние мгновенные чтения драйвера иногда
попадали в простой и показывали 0%. Эти исходные результаты сохранены;
повторная проверка с непрерывной очередью устранила неоднозначность.

Сырые результаты и код нагрузки: `Build/Diagnostics/resource-monitor/`:
`samples.json`, `top.txt`, `summary.json`, `sustained-gpu.json`,
`sustained-gpu-summary.json`, `veloedit-gpu-workload.swift` и проверочные Python-скрипты.

## Автоматические проверки

11 тестов прошли: CPU-дельты и переполнение счётчиков, отсутствие первого
CPU-замера, реальное чтение памяти/CPU, кэширование секундного замера,
валидация GPU-данных, расчёт памяти для страниц 4/16 КиБ, политика ограничения
нагрузки, охлаждение и отмена ожидания. Тесты выполнены из неизменяемой копии
исходников, поскольку другие файлы проекта редактировались во время работы.

Самостоятельный запуск счётчиков:

```sh
swiftc -O -parse-as-library \
  Sources/VeloEditCore/SystemResourceMonitor.swift \
  Sources/VeloEditCore/ProcessGPUUsage.swift \
  Sources/VeloEditCore/SystemGPUUsage.swift \
  Sources/VeloEditCore/SystemMemoryUsage.swift \
  Scripts/resource-monitor-probe.swift -o /tmp/veloedit-resource-probe
/tmp/veloedit-resource-probe 30
```

## Проверка приложения

Полная сборка `VELOEDIT_BUILD_SNAPSHOT=1 ./Scripts/build-app.sh` завершилась
успешно. Готовый пакет: `Build/VeloEdit.app`. Дополнительно прошла проверка
`codesign --verify --deep --strict`; в итоговом исполняемом файле проверено
наличие новых подписей GPU и памяти. Контрольные суммы исходников совпали с
копией для полной сборки. Журналы тестов, сборки и SHA-256 бинарного файла
сохранены рядом с замерами в `Build/Diagnostics/resource-monitor/`.

Визуальная проверка окна недоступна: Mac заблокирован. Уже запущенное приложение
не перезапускалось; для отображения новой версии виджета нужен перезапуск
VeloEdit после разблокировки. Результаты выше подтверждают реальные счётчики
и их привязку в исходниках/готовой сборке, но не заменяют проверку обновлённого
окна на экране.
