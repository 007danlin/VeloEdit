Обычные технические решения принимай самостоятельно. Не добавляй обязательные мастера, экраны проверки и диалоги восстановления в основной путь.

Подключай изменения к реальным действиям приложения и включай автономность по умолчанию. Не заканчивай работу на плане, внутренних типах, заглушках или скрытом флаге. Этапы в ТЗ — порядок выполнения полного задания.

Отдельно проверь воспроизведение и экспорт на реальных материалах; не выдавай unit-тесты за визуальную проверку или прослушивание. Реальные пользовательские проекты используй через изолированные копии.
