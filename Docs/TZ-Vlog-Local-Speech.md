# ТЗ на режим Влог и локальную обработку русской речи в VeloEdit

Дата: 4 октября 2026 года. Статус: исследование решений и требования к реализации.

Добавить «Влог» в начальный выбор стиля у «Умного режиссёра». При таком выборе VeloEdit сохраняет связный рассказ автора, локально распознаёт русскую речь, автоматически создаёт редактируемые субтитры и бережно обрабатывает звук. Все библиотеки, модели и технические параметры работают внутри приложения.

Рекомендация для первой интеграции: WhisperKit как нативный движок распознавания для Mac, многоязычная модель семейства Whisper large-v3, Silero VAD для определения речи и пауз. DeepFilterNet 3 проверить для очистки голоса. До фиксации основной модели обязательно сравнить качество с GigaAM v3 на русских записях. Результат сравнения может изменить выбор движка без изменения пользовательского сценария.

Под обработкой речи в этом ТЗ понимаются распознавание, сохранение исходного голоса, улучшение его разборчивости и монтаж. Синтез новой речи, клонирование голоса и переозвучивание требуют отдельной задачи.

Сравнительные запуски на пользовательских записях в рамках подготовки этого документа не проводились. Качество русского языка и скорость на Mac пока не измерены.

GigaAM особенно интересен из-за специализации на русском языке. Авторы публикуют преимущество на своих наборах и сравнении e2e-моделей; это основание включить его в проверку, а не подтверждение превосходства на видео с ветром и шумом дороги. [Результаты и описание моделей](https://huggingface.co/ai-sage/GigaAM-v3).

У GigaAM есть существенная интеграционная неопределённость: основной API показывает `word_timestamps=True`, однако просмотренный [ONNX inference API](https://github.com/salute-developers/GigaAM/blob/main/gigaam/onnx_utils.py) возвращает текст для ASR. Время слов в нативной ONNX-интеграции нужно реализовать и проверить отдельно. [Core ML execution provider ONNX Runtime](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html) существует, но сам факт его наличия не подтверждает ускорение конкретного графа GigaAM.

Для WhisperKit стартовый кандидат — многоязычный `large-v3-v20240930_626MB`, который текущий README относит к сжатому large-v3 Turbo. Сравнить его с полным large-v3 и GigaAM. Полный large-v3 и Turbo считать разными моделями; имя файла не заменяет точную идентификацию весов. [Рекомендации WhisperKit](https://github.com/argmaxinc/argmax-oss-swift#model-selection), [полный large-v3](https://huggingface.co/openai/whisper-large-v3), [large-v3 Turbo](https://huggingface.co/openai/whisper-large-v3-turbo).

При фиксации зависимостей сохранять лицензию каждого конкретного артефакта. Например, официальная Hugging Face карточка полного large-v3 помечена Apache-2.0, а карточка конвертированных моделей Argmax — MIT. Не записывать для всего стека одну общую лицензию по названию движка.

## Границы первой версии

Обязательный результат первой версии: выбор «Влог», локальная русская расшифровка, автоматические синхронные субтитры, сохранение законченных фраз, осторожное сокращение длинных пауз, приоритет голоса над музыкой, возможность отмены и ручной доработки.

Очистку голоса включать автоматически только после прохождения проверки качества. Результат должен сохранять тембр, окончания слов и естественные звуки в сценах без речи. Если выбранный способ ухудшает звук, использовать исходную дорожку и зафиксировать причину во внутреннем отчёте.

Перебивки по смыслу с продолжением голоса, автоматический выбор повторных дублей и более сложная работа с несколькими говорящими относятся к следующему этапу. Для первой версии достаточно корректно обработать последовательный рассказ одного автора и сохранить диалог без перестановки реплик.

Функция применяется к разговорным материалам любого содержания. Велопоездка — один из обязательных контрольных сценариев, без ограничения режима только этой тематикой.

## Изменение начального опроса

В текущем `DirectorConversationView` начальный шаг называется «Какое настроение важнее?» и содержит «Спокойное», «Киношное», «Динамичное». Отдельный `Picker("Стиль")` с `FilmPreset` расположен в параметрах фильма. Добавление нового элемента только в этот Picker не выполняет задачу пользователя.

Изменить существующий шаг опроса:

- Формулировка: «Какой стиль монтажа выбрать?».
- Варианты: «Спокойный», «Киношный», «Динамичный», «Влог».
- Подсказка: «Влог сохраняет рассказ автора и автоматически добавляет субтитры».
- Сохранить один шаг и существующий порядок опроса. Проверить размещение четырёх кнопок в узком окне.
- В текущем Picker стиля также показать «Влог», чтобы выбранный вариант был доступен после создания фильма.

Добавить `FilmPreset.vlog` с устойчивым сохраняемым значением `vlog`. В `SetupAnswer` добавить отдельный ответ для выбора этого пресета. `DirectorNarrativeMood` продолжает описывать темп и настроение: вариант «Влог» не добавлять в него как ещё одно настроение.

Обычные три ответа продолжают устанавливать прежние значения mood. При переключении с «Влога» на обычный ответ снять `preset.vlog`: восстановить предыдущий обычный пресет, а если он неизвестен — использовать действующий стандарт нового проекта. При повторном входе во «Влог» сохранять явно заданные пользователем музыку, звук, длительность и эффекты.

В итоговом описании ответа явно указать «Стиль: Влог» и состояние субтитров. Структурные поля проекта являются источником истины; повторное чтение текстовой сводки не должно превращать стиль в неподтверждённую инструкцию или запускать второй монтаж.

В пользовательском сценарии отсутствуют выбор ASR-движка, ONNX, Core ML, словари и параметры моделей. Существующий интерфейс состояния работы показывает понятные стадии: «Распознаю речь», «Собираю рассказ», «Добавляю субтитры».

## Правила стиля Влог

Первый выбор включает следующие значения по умолчанию, если пользователь ещё не указал иное:

| Область | Поведение |
|---|---|
| Монтаж | Сохранять порядок рассказа, законченные мысли, контекст и ответы |
| Исходный голос | Сохранять с исходной скоростью; не ускорять автоматически ради заданной длины |
| Музыка | Использовать заданную политику музыки, снижать её уровень во время речи |
| Субтитры | Создавать автоматически по распознанной речи, выбранной в финальный монтаж |
| Паузы | Сокращать только достаточно длинные и подтверждённые паузы между фразами |
| Длительность | Применять действующий выбор пользователя; режим «По материалам» учитывает длину связного рассказа |
| Эффекты | Соблюдать действующий выбор; на речевых склейках сохранять разборчивость и непрерывность |

Указания пользователя имеют приоритет над этими значениями. Выбор «Убрать звук исходников» действительно убирает голос. По умолчанию автоматические речевые субтитры тогда также не создаются; явная команда «оставь субтитры без звука» разрешает их для сохранённых видеосцен, имеющих подтверждённую расшифровку.

В первой версии не сокращать автоматически слова-паразиты внутри предложения, эмоциональные паузы, смех, дыхание после нагрузки и смысловые повторы. Слова «ну», «вот», «короче» сами по себе не являются основанием удалить фрагмент.

Если точная длительность несовместима с сохранением законченных фраз, сообщить об ограничении через существующий механизм выполнения задания. Не выдавать недостигнутую длительность за выполненную и не обрезать последнее слово для формального совпадения.

## Локальный речевой конвейер

Последовательность обработки:

1. Получить звук исходника, его временную шкалу и выбранный канал. Сохранить связь с исходным `assetID`, дорожкой и временем файла.
2. Подготовить служебное аудио для распознавания. Для Silero VAD использовать 16 кГц; параметры ASR брать из контракта выбранной модели. Звуковая дорожка для итогового фильма сохраняет полную частоту и качество.
3. Найти интервалы вероятной речи по всей доступной записи, включая визуально неподвижные фрагменты.
4. Распознать интервалы с контекстом на границах. Порционная обработка не должна пропускать начало слова или дублировать слова в перекрытиях.
5. Сформировать слова, фразы, пунктуацию, время, признаки уверенности и происхождение результата.
6. На основе фраз сформировать кандидатов для монтажа, затем применить существующие этапы истории и композиции.
7. После окончательного выбора и ретайминга сформировать субтитры по реально используемой речевой дорожке.
8. Подготовить согласованный звук, предпросмотр, экспорт и отчёт о выполнении.

Для «Влога» анализ речи обязателен во всех режимах AI, включая «Быстрый». Меняется допустимая стоимость визуального анализа, но наличие расшифровки не зависит от `audioAnalysisLevel == .deep`.

Нельзя требовать наличия визуальных shortlist-кандидатов до запуска ASR. Полезная речь сама создаёт основание для кандидата. Интервал без распознанных слов и интервал, где распознавание не запускалось или завершилось ошибкой, имеют разные состояния.

Для преимущественно русской записи использовать русский язык распознавания. При уверенном обнаружении другого языка многоязычная модель сохраняет исходный язык; перевод не включается автоматически. Русская речь с английскими названиями входит в обязательную проверку.

Один основной ASR-проход на исходник. Повторная обработка допускается для проблемного интервала по заранее описанным признакам: несогласованность VAD и ASR, повторы, выход таймкодов за границы, низкая уверенность. Не запускать все доступные модели для каждого файла по умолчанию.

## Выбор и встраивание движка

Начать технический прототип с адаптера WhisperKit, реализующего существующий `LocalSpeechRecognizing`. Параллельность задач внутри приложения ограничивать общим бюджетом памяти.

На этапе сравнения проверить GigaAM `v3_e2e_rnnt` и, при необходимости для выравнивания, CTC-вариант. Производственная интеграция GigaAM предполагает локальный ONNX Runtime с нативной обвязкой; Python допустим на исследовательском стенде и при подготовке моделей. Пользовательская установка Python, PyTorch, Homebrew, Docker или отдельного сервера не требуется.

GigaAM становится основным русским движком, если на отложенном контрольном наборе он уменьшает WER хотя бы на 10% относительно лучшего проверенного Whisper-варианта и одновременно проходит требования к таймкодам, упаковке, памяти и скорости. Это предлагаемый критерий выбора, а не уже полученный результат. При меньшей разнице предпочесть более простую устойчивую нативную интеграцию.

Если WhisperKit не проходит обязательные проверки, сравнить whisper.cpp с теми же весами. Принимать решение по конечному результату: правильный русский текст, синхронизация, стабильность длинных записей и воспроизводимая поставка. Не включать два Whisper-runtime в приложение без подтверждённой необходимости.

Для GigaAM обработку длинного аудио строить на общем локальном VAD и собственной сборке интервалов. Пользователь не получает требование зарегистрироваться на Hugging Face ради pyannote. Наличие timestamps в Python API не считать выполненной нативной интеграцией.

Apple Speech оставить совместимым существующим адаптером. Не использовать его скрытый переход на другой язык или отсутствие локальной модели как основание объявить обязательные субтитры готовыми. Облачного резервного распознавания нет.

## Качество расшифровки и временных меток

Хранить исходную расшифровку отдельно от текста для отображения. Допустима пунктуация и аккуратное оформление регистра; замена слов и изменение смысла требуют ручной правки. Языковая модель режиссёра не дописывает неразборчивые фразы и не восстанавливает предполагаемые факты.

Для чисел, сокращений и нормализованного текста сохранять соответствие отображаемых токенов произнесённым словам. Одна надпись «25 км» может соответствовать нескольким словам; количество текстовых токенов не определяет таймкоды.

При отсутствии достоверного времени отдельных слов использовать субтитр целой фразы с проверенными границами. Не распределять слова равномерно по длительности и не выдавать полученную оценку за измеренное время. Подсветку произносимого слова включать только при выполнении отдельного критерия точности.

Confidence разных движков не считать одной шкалой. Хранить собственные показатели модели, метод выравнивания и оценку качества; пороги калибровать на контрольной выборке. Состояние неизвестной уверенности не заменять значением 1.

Тишина, ветер, музыка и дорожный шум не должны порождать придуманные субтитры. VAD является одним из сигналов проверки, поэтому тихую речь проверять отдельно и не удалять только из-за низкого среднего уровня звука.

## Автоматические субтитры

Добавить в сохраняемые настройки независимую optional-политику субтитров с эффективными состояниями «Автоматически для влога», «Включены», «Выключены». Отсутствие поля в старом проекте сохраняет его прежнее поведение. Настройку передавать структурно в план и проверку выполнения.

Не добавлять обязательный вопрос в опрос. Для выбранного «Влога» существующий шаг титров получает подсказку: «Субтитры речи добавятся автоматически. “Без титров” отключает все надписи». Этот явный ответ отключает и титры, и субтитры. Команды «без субтитров», «добавь субтитры», «убери только названия частей» работают независимо в существующем чате.

Требования к результату:

- Создавать обычные редактируемые `TitleTimelineItem`, используя существующий рендерер и инспектор.
- Показывать только слова сохранённой в монтаже речи; удалённые части исходника не попадают в текст.
- Разбивать длинную фразу на читаемые смысловые группы: обычно 1–2 строки, без одиночных обрезанных слогов и пунктуации на отдельной строке.
- Стартовые ориентиры оформления: до 42 символов на строку для 16:9, до 30 для 9:16, до 20 символов в секунду, длительность 0,8–6 секунд. Это параметры для проверки на реальных кадрах; геометрия текста и фактическая речь имеют приоритет.
- При короткой реплике не растягивать надпись поверх следующего говорящего ради минимальной длительности. При быстрой речи разбивать текст или отметить проблему читаемости, сохраняя содержание.
- Согласовывать размещение с названиями частей, лицами и телеметрией; учитывать безопасные поля и вертикальное видео.
- По умолчанию использовать спокойные фразовые субтитры. Подсветка слов не является обязательным условием выпуска первой версии.
- Сохранять ручные исправления, удаления, стиль и отключение при повторной генерации. Стабильная привязка строится по речевому фрагменту и источнику, а не только по случайному UUID нового титра.
- Повторное создание субтитров идемпотентно: один и тот же набор не дублируется.

Предпросмотр и MP4 используют один набор субтитров. Предусмотреть выгрузку SRT и WebVTT через существующий экспорт без отдельного рабочего пространства. Для них рассчитывать время в шкале готового файла. При экспорте FCPXML соблюдать существующий механизм проверки возможностей: неподдерживаемое оформление отражать явно, без фиктивного обещания полного совпадения.

## Монтаж речи и согласование времени

Сохранять четыре различимых понятия: время исходного медиа, время служебного аудио распознавания, время монтажа и время итоговой композиции с перекрытиями переходов. Все преобразования должны быть воспроизводимыми и иметь единственный источник истины.

Начальный профиль обработки пауз: рассматривать паузы длиннее 0,9 секунды, оставлять примерно 0,25–0,4 секунды и защитные поля порядка 80–150 мс возле речи. Это стартовые параметры для настройки, не универсальные акустические нормы. Резать только при согласии границ фразы и анализа аудио; при сомнении сохранять паузу.

Каждое сокращение создаёт обычные редактируемые фрагменты существующего Timeline. Сохранять оригинальный файл и точное соответствие его интервалам. Микрофейды на аудиосклейках не должны съедать согласные. Жёсткие визуальные склейки допустимы при естественном звучании.

При ручных trim, split, ripple delete, перестановке, смене скорости и переходов пересчитывать субтитры через карту времени. Для переменной скорости линейного отношения общей длительности недостаточно. Для реверса речи автоматические субтитры не генерировать; уже привязанные автоматические элементы корректно отключать или перестраивать.

Субтитры привязаны к источнику голоса. На следующем этапе при перебивке изображение может смениться, а голос и субтитры продолжаются. Создавать второй текст из звука перебивки, если этот звук не звучит, запрещено.

## Обработка голоса и музыка

Базовая обработка включает выравнивание громкости фраз и контроль пиков существующими средствами аудиоконвейера. Музыка автоматически становится тише во время речи с плавными входом и восстановлением. Точные параметры подбираются по прослушиванию и записываются в профиль; они не меняют явную просьбу пользователя о громкости.

DeepFilterNet проверить на отдельной копии дорожки. Учитывать задержку обработки, начало и конец файла, длину результата и соответствие sample clock. ASR можно выполнять по исходной или очищенной служебной копии, если выбранный путь улучшает проверенные результаты; путь обработки входит в ключ кэша.

Обработанная дорожка используется одинаково в предпросмотре и экспорте. Исходник остаётся доступен для отмены. На сценах природы без речи избегать постоянного подавления атмосферы. Сильный ветер, перегруз микрофона и одновременные голоса не объявлять полностью восстановленными без проверки.

## Модели и работа без сети

После установки необходимых весов импорт, VAD, ASR, монтаж, обработка голоса, субтитры и экспорт работают при отключённой сети. Автоподбор музыки без сети использует доступную локальную библиотеку. При отсутствии подходящих локальных треков сохранить голос и объяснить отсутствие музыки; недоступность конкретного явно выбранного трека сообщать отдельно. Онлайн-подбор саундтрека не должен блокировать речевой конвейер. Проверить offline-сценарий и с автоподбором музыки по умолчанию, и с локальным треком, и с вариантом «Без музыки».

Есть два допустимых способа доставки: установленный вместе с приложением пакет моделей либо однократная загрузка локального речевого пакета через существующий механизм установки AI-компонентов. Для полностью автономной установки предусмотреть перенос готового пакета с диска. Первичная загрузка из интернета и локальное выполнение явно различаются.

В пользовательском интерфейсе установки показывать назначение пакета, точный размер и прогресс. Названия движков не требуют выбора. Установка весов не отправляет аудио или расшифровки. Без установленных весов и без сети приложение сообщает о недоступном речевом компоненте до создания «Влога» и сохраняет проект.

Технические требования к пакету:

- Зафиксированные версия runtime, модель, revision, SHA-256 всех файлов, токенизатор и параметры предобработки.
- Атомарная установка, возобновление загрузки, проверка целостности и доступного места.
- Загрузка из явного локального пути при работе. Отключены неявные обращения SDK к каталогу моделей и скачивание недостающих файлов во время распознавания.
- В комплекте присутствуют лицензии и notices выбранных runtime, весов и зависимостей.
- На машине пользователя не выполняются конвертация моделей, установка пакетов и получение произвольного remote code.
- Прогрев и компиляция Core ML выполняются с видимым состоянием работы и учитываются отдельно от повторных запусков.

## Хранение и устойчивость

Расширить речевые данные optional-полями либо отдельной версионированной записью: источник и дорожка, язык, runtime и версия, идентификатор и hash модели, версия VAD и alignment, настройки подготовки аудио, интервалы, слова, фразы, необработанные оценки уверенности и происхождение таймкодов.

Ключ речевого кэша включает content hash исходника, выбранную аудиодорожку и канал, версию декодирования и ресемплинга, модель, язык, параметры VAD, обработки звука и выравнивания. Смена модели не переиспользует старую расшифровку как новую. Обычные правки титров и монтажа не запускают повторный ASR.

Обработку длинного исходника сохранять по завершённым порциям. После отмены, перезапуска или нехватки памяти продолжать с проверенного результата. Не загружать целиком многочасовой PCM в память. Одновременные VLM, ASR и экспорт согласуются с существующим учётом ресурсов; по умолчанию работает один тяжёлый ASR worker.

Новая речь, субтитры и монтаж коммитятся с проверкой ревизии проекта. Запоздавший результат старой задачи не затирает ручные правки. Состояния «готово», «речи нет», «частично», «модель недоступна», «ошибка» и «отменено» должны быть различимы.

При частично неразборчивой речи сохранить исходный голос, построить только подтверждённые субтитры и сообщить о неполном результате. При отсутствии речи можно завершить визуальный монтаж в выбранном стиле без субтитров с понятным пояснением. DSP-границы без текста не являются готовой расшифровкой.

## Проверка качества и критерии приёмки

Числа ниже являются предлагаемыми требованиями проекта. Они не взяты из рекламных измерений движков и не обозначают уже достигнутый результат. Если контрольный прогон выявит недостижимый порог, зафиксировать результат и пересмотреть требование явно, без скрытого снижения качества.

Собрать локальный корпус минимум из 60 минут речи не менее шести говорящих. Включить спокойную речь в помещении, улицу, велосипед и ветер, музыку на фоне, тихий голос, эмоциональные паузы, диалог, имена и географические названия, числа и смешение русских и английских слов. Дополнительно проверить 15 минут тишины, музыки и шумов без речи и один файл не короче 60 минут на устойчивость. Пользовательские записи не отправлять во внешние сервисы.

Для каждого класса предусмотреть ручную эталонную расшифровку. Выделить не менее 20 минут отложенного корпуса, не используемого для выбора порогов; по возможности отделить по говорящим. Для проверки синхронизации вручную разметить начало и конец минимум 500 слов, включая слова на границах порций и монтажных склеек.

| Проверка | Критерий |
|---|---|
| Русский текст | Нормализованный WER не выше 8% на чистой речи и 18% на умеренно шумной. Отдельно публиковать результат каждого класса; сильный ветер не смешивать с чистой речью |
| Методика WER | Одинаковая нормализация чисел, регистра, пунктуации и «ё/е» для всех кандидатов; WER = сумма замен, удалений и вставок / число слов эталона |
| Смысл и имена | Отдельный ручной отчёт по отрицаниям, числам, именам и местам; хороший общий WER не скрывает систематическую потерю «не» |
| Покрытие речи | Не менее 98% длительности разборчивых речевых фраз сохранённого монтажа имеют соответствующие субтитры; точность их текста оценивается отдельно через WER. Пропущенные интервалы перечислены |
| Синхронизация | На вручную размеченных границах 95-й процентиль абсолютной ошибки начала и конца слова не выше 200 мс; для включения подсветки слов — не выше 120 мс |
| Фразовые субтитры | При недоступном точном word alignment проверить фразовые границы отдельно; нет фиктивной подсветки и текста от удалённых частей |
| Отсутствие речи | Ноль опубликованных придуманных фраз на контрольных 15 минутах музыки, тишины и шумов |
| Монтаж | На контрольных примерах нет обрезанных слов, удалённых отрицаний, переставленных ответов и изменения смысла; проверяется прослушиванием |
| Очистка звука | Слепое A/B-прослушивание минимум 20 отрывков: разборчивость не хуже исходника, отсутствуют потерянные окончания и заметный искусственный тембр; провальные условия отключают обработку |
| Таймлайн и экспорт | После trim, split, ripple, смены скорости и переходов субтитры совпадают с итоговым звуком; между preview и экспортом нет добавочного расхождения более одного выходного кадра |
| Повторная генерация | Нет дубликатов, ручные исправления и отключение сохранены; неизменный исходник не распознаётся повторно |
| Автономность | Полный сценарий с установленными моделями проходит при заблокированном внешнем сетевом доступе; никаких облачных вызовов или обязательных токенов |
| Переносимость | Подписанное приложение запускает речь на чистой машине без среды разработки, пользовательского Python и системного FFmpeg |
| Совместимость | Старые проекты открываются без новой автоматической речи и без изменения сохранённого монтажа |

Производительность измерять на Apple Silicon с 16 ГБ и 32 ГБ памяти, указав точный чип, macOS, модель и её hash. Отдельно измерять холодный запуск, прогретый запуск, время VAD, ASR, выравнивания, peak memory и размер пакета. Начальная цель: прогретое распознавание 10 минут речи не дольше 10 минут на M1 с 16 ГБ; на M4 с 32 ГБ — не дольше 5 минут. Это бюджет этапа ASR, без видеоэкспорта; достижение предстоит проверить.

Предлагаемый дополнительный бюджет памяти речевого worker — до 4 ГБ на конфигурации 16 ГБ, с последовательным запуском тяжёлых моделей. Учитывать footprint процесса и доступные метрики Core ML, не ограничиваться размером файла весов. Отмена должна отражаться в UI сразу; тяжёлая работа прекращается не позднее пяти секунд, при необходимости через завершение изолированного worker с сохранением готовых порций.

## Этапы реализации

1. **Сравнение решений.** Подготовить корпус, замерить WhisperKit, GigaAM и контрольный полный large-v3; проверить таймкоды, ONNX-путь и лицензии артефактов. Сохранить отчёт с выбранным runtime, весами, версиями, параметрами и причинами выбора.
2. **Режим и локальная речь.** Добавить «Влог» в существующий шаг, совместимое хранение настроек, пакет моделей, VAD и ASR по всей речи. Подключить речевые кандидаты, прогресс, отмену и кэш.
3. **Субтитры и звук.** Автоматические редактируемые субтитры, единая карта времени, команды отключения, сохранение ручных правок, SRT/VTT, приоритет голоса и проверенная очистка.
4. **Бережный монтаж.** Сокращение пауз между законченными фразами, проверки смысла, точной длительности и стабильности длинных записей.
5. **Приёмка приложения.** Контрольные проекты, offline-проверка, preview/export, восстановление и переносимость. После изменений исходного кода или ресурсов выполнить `./Scripts/build-app.sh` и проверить полученный `Build/VeloEdit.app`; одного `swift build` недостаточно.

Следующий отдельный этап после принятой первой версии: смысловые перебивки с непрерывным голосом, выбор лучших повторных дублей и более сложные диалоги. Их отсутствие не блокирует первую версию, но модель данных и привязка к аудио должны позволять это развитие.
