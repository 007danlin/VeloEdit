# Публикация veloedit.ru

Основной сайт обслуживает GitHub Pages из репозитория `007danlin/VeloEdit`.
Workflow `.github/workflows/pages.yml` публикует папку `website` при изменениях
в `main`, публикации/редактировании релиза и ручном запуске. GitHub Pages использует
режим GitHub Actions и custom domain `veloedit.ru`; HTTPS должен быть включён.

DNS остаётся в Cloudflare. Записи `veloedit.ru` и `www.veloedit.ru` ведут на
`007danlin.github.io` в режиме DNS Only (для корня Cloudflare выполняет CNAME
flattening). Почтовые записи не меняются. GitHub Pages перенаправляет `www` на
основной домен. Трафик сайта не проходит через прокси Cloudflare.

Кнопка скачивания сначала использует GitHub API, затем локальный `release.json`.
Workflow обновляет этот снимок и копирует подписанный `appcast.xml` из последнего
GitHub Release при каждом развёртывании. Cloudflare Functions на GitHub Pages не
исполняются. Само приложение продолжает получать обновления напрямую из GitHub.

Резервная копия остаётся в Cloudflare Pages: проект `veloedit`, ветка `main`,
команда `exit 0`, каталог `website`, адрес `veloedit.pages.dev`. Для отката вернуть
DNS-записи на `veloedit.pages.dev` и проверить custom domains/HTTPS в Cloudflare.

Локальный просмотр: `python3 -m http.server 8765 --directory website`.
Проверка выбора DMG: `node --test Tests/Website/release.test.mjs`.
После публикации проверить главную, `/support/`, скачивание DMG и
`/updates/appcast.xml`.

## Поддержка проекта

Ссылка поддержки в верхней панели на широких экранах открывает модальное окно
с QR-кодом. На экранах до 760 px JavaScript переключает её на прямой перевод
Ozon Банка. Без JavaScript и при открытии в новой вкладке с компьютера доступна
страница `/support/`. README репозитория и GitHub Sponsor через
`.github/FUNDING.yml` ведут на `https://veloedit.ru/support/`.

Крестик, Escape и щелчок по затемнённому фону закрывают модальное окно.
Крестик отдельной страницы возвращает на главную; на узком экране под QR
есть прямая ссылка на перевод, чтобы не сканировать собственный экран.
Страница QR содержит `noindex, nofollow` и не включается в sitemap.

Оригинал QR-кода владельца хранится в `assets/support-qr.png` без изменений.
При смене реквизитов обновлять изображение и прямой адрес оплаты одновременно
в `support.js` и `support/index.html`:
`https://finance.ozon.ru/apps/sbp/ozonbankpay/fb932411-2764-4c38-9bb9-344feeb13dca`.
Логика QR загружается отдельно от поиска релиза; поддержка не зависит от GitHub API.
Сайт не запрашивает платёжные данные; сумму пользователь вводит на странице банка.

Формулировка кнопки — «Поддержать VeloEdit». Контекст объясняет пользу поддержки
для разработки; ссылка на реальные релизы позволяет увидеть результат работы.
В README также перечислены способы помочь без доната.
Нет неподтверждённых счётчиков доноров, срочности, обещаний конкретных сроков или
сумм, якобы достаточных для отдельной функции. Пользователь сам выбирает сумму на стороне банка.

Основания для решения:

- [NN/g: понятная цель, использование средств и простой путь к донату](https://www.nngroup.com/articles/donations-nonprofit-charity-online/).
- [Исследование University of Canterbury](https://ir.canterbury.ac.nz/items/f6640001-b5a2-42f1-ad4c-00470e5ae213): изменения оформления кнопки сами по себе не дали значимого эффекта на готовность донатить в описанных экспериментах.
- [GitHub: настройка Sponsor через FUNDING.yml](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/displaying-a-sponsor-button-in-your-repository).

Исследования относятся к благотворительным сайтам, поэтому это ориентир для
дизайна, а не доказательство роста донатов именно VeloEdit. Название и размещение
можно проверить на реальной аудитории по статистике донатов.

Ссылка на сайте помечена `rel="nofollow"`; такой же атрибут задан в HTML-ссылке
README (итоговое поведение GitHub контролирует сама платформа). Это рекомендация
поисковым роботам, а не запрет доступа: произвольные боты могут её игнорировать,
а ссылка остаётся публичной. `FUNDING.yml` не поддерживает настройку `rel`.
Защиту самой платёжной страницы может обеспечить только банк.
См. [Google: атрибуты исходящих ссылок](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links).

## Защитные заголовки резервной копии Cloudflare

GitHub Pages не применяет файл `_headers`. Перечисленные ниже заголовки относятся
к резервной копии Cloudflare; для основного сайта действуют заголовки GitHub Pages.


`website/_headers` задаёт CSP для статических страниц: скрипты и стили только с
нашего сайта, запросы данных — с сайта и `api.github.com`. Запрещены плагины,
встраивание страниц в iframe, подмена base URL и отправка HTML-форм. Локальная
форма `method="dialog"` продолжает закрывать QR-окно без отправки данных.
Обычные ссылки на GitHub Releases и Ozon Банк остаются доступны.

HSTS включён на 30 дней только для текущего хоста, без `includeSubDomains` и
preload, чтобы не затрагивать другие сервисы домена. Для отката удалить или
изменить `_headers` и опубликовать обычным push; уже полученный браузером HSTS
действует до истечения срока или получения `max-age=0` по HTTPS.

Cloudflare применяет `_headers` к статическим ответам, но не к ответам Pages
Functions. Функция `/release.json` возвращает JSON через `Response.json` и не
генерирует HTML; при добавлении HTML-функций заголовки нужно задавать в коде.
После публикации проверять заголовки главной и `/support/`, появление актуальной
ссылки на DMG и открытие/закрытие QR-окна. Обычный `python -m http.server` не
применяет `_headers`.
